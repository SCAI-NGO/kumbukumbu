# The fixes of the 0.6.0 UI tests

Status: approved by Chris, 2026-11-19, decisions included.

## 1. Goal and decisions

The MCP and browser suite of 0.6.0 (#261, report `docs/superpowers/overnighter/2026-11-19-tests-0-6-0-report.md`) found fourteen bugs and open points. This run fixes those outside the discreet and skills code. A sibling run, `feature/security-fixes-0-6-0`, fixes the security review's findings together with F-10, F-11 and M-01, in parallel. Chris hand-tests both on 2026-11-20.

Decisions, each with Chris's reason:
- **Two runs side by side.** Their code is disjoint (§7), so both pull requests are ready in the morning, before the hand tests.
- **F-09: the warning colour counts as the spec's "red".** From 50 notes the line and the count use the theme's warning token (orange), and the publish bundles spec's wording says "the warning colour" instead of "red", in all three places (around lines 39, 40 and 96); this run edits that spec for it. Why: 50 notes is a hint, not a danger; red is for what goes wrong. The test checks for the warning token, not for a hue near red.

Kumbu²'s principles hold for every item: campy, human-centric, invite and lead, honest.

## 2. The fixes

Each finding's "Expected" in the report's section "Findings" is the target, and its "Likely place" the starting point (not a promise).

| Id | Fix |
|---|---|
| F-08 (Medium) | Every note of a bundle carries the publication bar, and it turns yellow, with the words the single-note bar uses, when the copy is older than the note (publish bundles spec, decision 7). **Decided on the client, for the owner only**, from what the client already gets: ask `usePublication(start)` for each bundle's start, and the bar is yellow when the note's `lastWriteAt` is later than the start's `snapshotAt`; with several bundles, yellow if any one is older. Members keep "Published by the vault's owner". The bundled bar gets no "Update copy": the start's name links to the note where the copy is updated. No server change. |
| F-12 (Medium) | Shift+F10's keyboard menu takes the focus on its first item once it is placed and visible; Esc closes it with the caret back where it was; the arrow keys and Tab work in it. A test in the browser suite proves it in Chromium, since jsdom focuses a hidden element and the Vitest test passed while the bug was there. |
| F-13 (Medium) | The menu is placed again when its items or its size change, so it stays within the window, flipping above where there is no room, also straight after a note opens. |
| M-03 (Medium) | `mv` and `archive` keep a note's creation time as it was: `created` unchanged and `createdAtLeast` unchanged (false stays false), also after a later `rm` and `restore` (graph backend spec §5). The likely place is `src/Kumbu.Core/Notes/NoteMover.cs` (around 259: carry `NoteCreation.Of(current)` into `CreatedAt`/`CreatedAtLeast` when they are null); check the checkpoint moves (`Checkpoints.cs` around 652 and 672) and the trash restore too. Nothing at rest changes: the encrypted payload already carries both. |
| F-05 (Low) | An unticked note is listed under "Stays behind" with "taken out by you", not as an empty box under "What goes out". Beside it a **Take back in** button (at least 48 px) ticks it again and moves it back. |
| F-06 (Low) | From 50 notes the "+N notes" count beside the depth takes the warning colour, as the line under the list does (§1, F-09). |
| F-07 (Low) | Before publishing, the dialog lists every embedded PDF under "Stays behind" as "a PDF (not published)"; the preview already carries them in `plain`, **by file name** (`manual-x.pdf`), not by path, so the dialog lists the name, and `publish.spec.ts` (around line 464) is corrected from the path to the name: that corrects the test to what the server gives, it doesn't loosen it. Only PDFs are listed (by extension); the `pdfsNotYet` sentinel is not shown as an item. |
| F-09 (Low) | §1: the publish bundles spec's "red" becomes "the warning colour"; the test asserts the warning token. |
| F-14 (Low) | In Read mode the keyboard menu opens where the dock's own ⋯ menu opens, the same place and direction. |

The UI tests' `test.fail()` markers or retries for these come out once the fix holds; a test is never loosened to pass.

## 3. End-to-end example

Alice publishes `/Work/Pump/Overview.md` with depth 2.
1. The dialog lists Beta, which she unticked, under "Stays behind", with "taken out by you", and the embedded `datasheet.pdf` as "a PDF (not published)" (F-05, F-07).
2. She publishes. Later she edits Gamma, which went out with the bundle: Gamma's bar turns yellow and says the copy is older (F-08).
3. In Gamma, in Write mode, she presses Shift+F10: the menu opens with its first item ("Copy file path") focused, fully on screen; ↓ moves, Esc closes it, and her caret is where it was (F-12, F-13).
4. Her agent runs `mv /Work/Pump/Delta.md /Work/Archive/` on Delta, which nobody has edited since it was made: the graph's node view (`GET /api/graph/node`) still gives Delta's creation time, not "at the latest" (M-03).
