## Settled designs (from the brief's open points; the report logs them as decisions)

- **D1, the collection.** Token documents live in a collection of their own, `ai_links` (`AiLinkDocument`): `_id`, `vault` (string), `publication` (the publication document's `ObjectId`), `lookup` (bytes, HKDF of the token), `slot` (the publication key and the owner's id, sealed under a key derived from the token, context `ai-link:{L}:{publication id}`), `expiresAt`, `count`. Indexes: `lookup` unique, `vault`, `publication`, and a TTL index on `expiresAt` (`ExpireAfter = TimeSpan.Zero`), which only tidies up. The collection is **not** in `ContentCollections` (it would count towards the owner's storage and be visible in the storage figures); `VaultCatalog.DeleteVaultsAsync` deletes it by `vault` beside `ContentCollections`, inside the transaction and in the sweep after it. `PublicationStore.DeleteCopyAsync` deletes by `publication`, `DeleteCopiesOfVaultsAsync` by `vault`. Deleted token documents are **not** added to the counts these methods return (a deletion receipt would otherwise tell how many AI links readers made).
- **D2, the owner check.** The owner's id is sealed in the token's slot beside the publication key (as the reader slot holds it, publish design decision 7); nothing names the owner in the clear. Every fetch opens the slot and checks `UserDocument.Active`, as `ReaderApi.OpenAsync` does.
- **D3, the paths.** `ReaderPaths.Is` also matches `/s/t` and everything below it (`AiLinkApi.Path`). `GET`/`HEAD` `/s/t/{token}` and `/s/t/{token}/files/{index}` are mapped with `MapMethods`, the index bound as a **string** and parsed with `NumberStyles.None` as `ReaderApi.FileAsync` does (an `int` route parameter would turn `/files/x` into a 400); `MapFallback("/s/t/{**path}", …).AllowAnonymous()` (without it `CallerMiddleware` answers 401) answers every other method and path below `/s/t` with the plain-text 404, before `MapFallbackToFile`. The link and the Markdown's file base are both built with `Publications.BaseUrl(http, options.Value)`, never by hand.
- **D4, L-02's state.** `SkillUpdates.PublishingOff = "publishing-off"` (the same string as `ReaderApi.OffType`), left out of `checkedPaths` as null is; the web shows the spec's sentence for it in place of the update state, and offers no Review for it.
- **D5, the image references.** `MarkdownLink.Parse` (`src/Kumbu.Core/Links/MarkdownLink.cs:69`, which skips fenced code, inline code and wikilinks) finds the embeds; an embed whose destination is exactly `f/<n>` is rewritten: with `n` among the copy's files, its destination becomes `<base>/s/t/<token>/files/<n>` and ` (<media type>)` follows the closing parenthesis; with `n` not among them, the embed is left out. The rewrite splices by offsets into the original string (line offsets computed from the `\n` split `Lines.Split` uses, so a `\r` stays where it is): everything else stays byte for byte. Indented code blocks aren't skipped by `MarkdownLink.Parse`; the fair copy writes `![…](f/n)` only for embeds it found outside code, so an indented `![x](f/0)` can only be a user's literal text, which would then be rewritten: a harmless divergence from the page, noted in the report.
- **D6, the Markdown.** `# <title>` (line breaks in a title become spaces), a blank line, `A published note, snapshot of <yyyy-MM-dd HH:mm> UTC; links to other notes are plain text.`, a blank line, the rewritten Markdown. The server has no reader's time zone, so UTC, said.
- **D7, refusals at `/s/t/`**, all plain text: the limits (`ReaderRead` for the Markdown, `ReaderFileRead` for a file) first, `429` with `Retry-After` and `Too many requests; try again in a minute.`; then a network or server that `ReadersBlocked` blocks, the 404 sentence; then publishing off, `404` with `ReaderApi.OffSentence`; then the token. Unknown, expired, used-up tokens never call `ReaderFailed`.
- **D8, the ceiling.** `50 + 5 × files` of the copy read at the moment of the request; the count goes up in one `FindOneAndUpdate` filtered by `_id`, `expiresAt > now` and `count < ceiling`; a request that doesn't match answers the 404. A link made while its publication is being withdrawn may be inserted after `DeleteCopyAsync`; it opens nothing, since every fetch reads the publication document by `_id`, and the TTL removes it.
- **D9, making a link.** `POST /api/s/ai-links` in `ReaderApi`'s group: `OpenAsync` with the reader cookie and `limits.ReaderRead`, then the copy header checked as `FileAsync` checks it (a mismatch answers the 404 and keeps the cookie). The answer: `200`, `{ "link": "<base>/s/t/<token>", "expiresAt": "<ISO>" }`; `/api` already sets `Cache-Control: no-store`. A request size limit of 1024 bytes, as the POST beside it.
