## Rules for every task

- Environment: `source /tmp/claude-0/env.sh` (Node 26 on the path, `DOTNET_CLI_TELEMETRY_OPTOUT=1`, `MSBUILDDISABLENODEREUSE=1`, `UseSharedCompilation=false`, `KUMBU_TEST_MONGO`, `TESTCONTAINERS_RYUK_DISABLED=true`). `UseSharedCompilation=false` matters: the Roslyn compiler server otherwise inherits the lock's file descriptor and holds `/tmp/heavy.lock` after the build ends.
- Every build and every test run of more than one class runs as `flock /tmp/heavy.lock <command>`. One heavy run at a time, across all worktrees.
- Build: `flock /tmp/heavy.lock dotnet build --configuration Release --no-restore` (after `dotnet restore --locked-mode` once per checkout).
- One core class: `flock /tmp/heavy.lock dotnet test --project tests/Kumbu.Core.Tests --configuration Release --no-build -- --filter-class "*<Class>"`; one server class the same with `tests/Kumbu.Server.Tests`.
- One web file: `pnpm -C web test --run <file>` (paths relative to `web/`).
- Red first: each new or changed test is run and seen to fail on its own assertion before the fix. Then green. Then every mutation of the fix, one at a time: revert a single line or condition of the fix, run the test, see it fail, restore with `git checkout -- <file>` (or re-apply the saved diff when the file holds the fix uncommitted: keep the fix in a patch, `git diff > /tmp/claude-0/<task>.patch`, mutate, test, `git checkout -- <file> && git apply /tmp/claude-0/<task>.patch`).
- Subagents commit locally on the branch, staging files by name; they never push, merge or switch branches. Commit messages imperative, free-form, the finding id in the body, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Web types by hand in the feature's API module; `web/src/api/schema.d.ts` is not regenerated. No new dependency.
- Not touched (spec §6, §7): `Auth/`, `CallerMiddleware`, `Crypto/`, sharing and roles, sync, OAuth, WebDAV's authentication, `src/Kumbu.Server/Api/Security.cs`, the server's publishing; the sibling's code (`web/src/discreet/`, `web/src/windows/`, `web/src/palette/`, `web/e2e/discreet/`, the skills code). In `web/e2e/palette/palette.spec.ts` only the tests #8, #9 and #10.
- **Browser and MCP tests (red and green) run centrally, by the coordinator, never by a subagent:** the stack is one per machine (port 8080) and is built from one checkout. Exact commands, every time: `docker stop kumbu-test-mongo`; `E2E_PROXY_CA=/root/.ccr/ca-bundle.crt flock /tmp/heavy.lock web/e2e/stack/up.sh`; `pnpm -C web exec playwright test --project=setup`; then `pnpm -C web exec playwright test --no-deps --project=desktop --project=phone --grep "<title or tag>"` (browser) or `pnpm -C web exec playwright test --no-deps --project=mcp --grep "<title>"` (MCP); `web/e2e/stack/down.sh`; `docker start kumbu-test-mongo`. The red run is made once, on the baseline with the findings' markers lifted (worktree `wt/red`), and the green run on the branch with the fixes. The subagents edit the e2e files (markers, assertions) in their fix commits but run only Vitest and xUnit.
- After a fix's commit: a fresh reviewer subagent checks spec compliance and code quality against the spec and this task, not against the implementer's summary. Findings are fixed and re-reviewed until clean.
