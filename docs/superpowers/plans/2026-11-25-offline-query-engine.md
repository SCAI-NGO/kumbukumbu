# The offline query engine — plan

Spec: `docs/superpowers/specs/2026-11-24-queries-data-side-design.md` (§7: two engines, one set of cases; §9: the TypeScript evaluator "after the C# one has fixed the semantics"). ADRs 0026 and 0027.

Goal: a TypeScript query engine in `packages/eidolon-core/src/query/` that passes every case in `tests/query-conformance/`, as the C# engine in `src/Kumbu.Core/Queries` does. It is the engine the offline mode will run queries with; wiring it into the web app or an offline `sh` is not part of this plan (that comes with the query UI).

## Global constraints

- **A port, not a redesign.** The C# engine is the reference: `src/Kumbu.Core/Queries/*.cs`, `src/Kumbu.Core/Tags/TagReader.cs`, `src/Kumbu.Core/Sections/Outline.cs` (`FrontmatterEnd`, `Fences`), `src/Kumbu.Core/Board/Frontmatter.cs` (`MaxValues` 10 000, `MaxDepth` 64, `TooLargeProblem`). Same names where TypeScript allows (`Properties.read`, `ExpressionParser.parse`, `Evaluator`, `Base.parse`/`run`, `Query.read`/`run`/`check`), same limits (expression length 10 000, nesting 64, base nodes 10 000), same error codes (`syntax`, `unknown-function`, `unknown-method`, `unknown-formula`, `formula-cycle`, `regex`, `too-deep`, `base`, `unknown-view`, `no-base`, `params`, `unknown-param`, `missing-param`, `param-value`) and, where practical, the same messages.
- **The cases decide.** Where the C# code and a case disagree, the case wins and the disagreement is reported (it would be a C# bug). Where a case is silent, the C# behaviour is the semantics. Never change a case to fit the TypeScript engine; never add `pending: [ts]` to get green.
- **The runner reads the cases in place**: `test/query.conformance.test.ts` reads every `*.yaml` below `tests/query-conformance/` (path from the package root: `../../tests/query-conformance`), fails on an empty folder or a file it can't read, honours `pending: [ts]` as a visible skip (`test.skip` with the file name), and compares as the C# runner (`tests/Kumbu.Core.Tests/Queries/ConformanceTests.cs`) does: values written as in the README's table, properties one line per property sorted by code point, rows as `cell | cell` lines.
- **The boundary** (`packages/eidolon-core/README.md`, `test/boundary.test.ts`): no DOM, no Node in `src/`, dependencies only under permissive licences. Two new dependencies, both checked by the boundary test: `yaml` (ISC; YAML 1.2, gives scalar styles, aliases and duplicate keys) and `re2js` (MIT; RE2 in pure JavaScript, linear-time matching). Pin exact versions in `package.json` as the package's other entries are pinned (check the style there), update the root `pnpm-lock.yaml` with `pnpm install` at the root.
- **Regular expressions in linear time.** A pattern is anyone's input: a query note in a shared vault is written by others, and a backtracking pattern could hang the tab. The C# engine compiles with `RegexOptions.NonBacktracking`; the TypeScript one compiles with `re2js` (flags `i`, `m`, `s` mapped; `g` and `u` accepted and without effect on `matches`, as in C#). A pattern RE2 rejects is the `regex` error. Never `new RegExp(pattern)` on a query's pattern.
- **YAML as the C# engine reads it.** Parse frontmatter, bases and `params:` with the `yaml` package so that every scalar stays its source text plus its style (plain or quoted): use the failsafe schema or read `Scalar.type`, then type it with the same rules as `Properties.Scalar`/`Inferred` (YAML 1.2 core schema: `true/True/TRUE`, `null/Null/NULL/~/empty`, numbers per `NumberPattern`, no hex, octal or infinities). A YAML error is a `problem` (frontmatter) or a `base`/`params` error. Duplicate keys are a problem (`The frontmatter has the key 'x' twice.`). Aliases are resolved and counted against the budget (values ≤ 10 000, depth ≤ 64) so an anchor bomb is `TooLargeProblem`, never a hang; set the parser's own alias limit too.
- **Values.** A discriminated union (`{ kind: "text", text }`, …) for null, text, number, boolean, date, datetime, list, object, file, note-ref, regex. Dates without a zone, kept as their parts or a normalised ISO string (`yyyy-MM-dd`, `yyyy-MM-ddTHH:mm:ss` with up to 7 fractional digits); never through a zoned `Date` that could shift a day. A number shown as text uses .NET's round-trip form as the C# engine's `Display` does (match the cases; for exponents, JavaScript writes `1e+21` where .NET writes `1E+21`: follow .NET, since the cases and the server's output are .NET's).
- **Text rules as .NET's.** Case-insensitive property names (`OrdinalIgnoreCase`) via the core's existing `foldCase` in `src/links/text.ts`; ordinal comparisons by UTF-16 code unit (`textOrder` in `src/links/order.ts` where it fits); `char.IsLetter`/`IsLetterOrDigit` as `\p{L}`/`[\p{L}\p{N}]`, `IsWhiteSpace` as JavaScript's `\s`; reuse `splitLines`, `frontmatterEnd`, `codeLines` from `src/links/text.ts` rather than copying them (extend `text.ts` with the open-fence information `Outline.Fences` gives, if needed, without changing what its existing callers get).
- **The sync code stays untouched:** nothing in `src/engine`, `src/api`, `src/live` or `test/fakes` changes (the Obsidian plugin vendors them).
- **Caching (ADR 0027).** `Properties.read` caches by content as the C# `ConditionalWeakTable` does; strings can't be keys of a `WeakMap`, so use a bounded `Map` keyed by content (last 20 000 entries, oldest out) together with the types it was parsed with. Say why in a comment.
- **Style.** `// SPDX-License-Identifier: AGPL-3.0-or-later` first; British English; comments only where the reasoning isn't obvious, at the density of `src/links/`. Tests with Vitest; no unit tests that repeat what a conformance case already shows (unit tests only for what one implementation has inside: parser limits, budget, the regex engine choice, the cache).
- **Checks before each commit:** `pnpm -C packages/eidolon-core test` and `pnpm -C packages/eidolon-core build` green. The C# suite is not touched.

## Task 1: values, property types and properties

Files: `src/query/value.ts`, `src/query/propertyTypes.ts`, `src/query/properties.ts`, `src/query/tags.ts` (port of `TagReader.Of`: a note's tags, frontmatter first, as Obsidian reads them), `test/query.conformance.test.ts` (the runner, with the `properties/` part; the other folders' cases are not run yet: the runner lists them as `test.todo` with their file names until their task lands, so nothing is skipped silently), `test/query.properties.test.ts` (budget, duplicate keys, the cache), `package.json` (+ `yaml`), `pnpm-lock.yaml`.

Port `Value.cs`, `PropertyTypes.cs` (`read(json)` and `named(name)`), `Properties.cs` (`read(content, types)` → `{ values, problem }`), `QueryNote.cs` (`QueryNote` with `path`, `content`, `properties`, lazy `tags`). Done when every case in `properties/` passes.

## Task 2: expressions

Files: `src/query/expr.ts`, `src/query/parser.ts`, `src/query/errors.ts` (`QueryError` with `code`, `expression`, `position`; `QuerySyntaxError`; `inExpression`), `src/query/evaluator.ts`, the runner's `expressions/` part, `test/query.parser.test.ts` (length and nesting limits, positions in messages, the regex literal), `test/query.regex.test.ts` (a catastrophic pattern such as `/(a+)+$/` over 30 `a`s and a `!` returns quickly; a lookahead is the `regex` error), `package.json` (+ `re2js`).

Port `Expr.cs`, `ExpressionParser.cs`, `QueryError.cs`, `Evaluator.cs` (with its `FunctionReference`, `MethodReference`, `FieldReference` lists, exported, as `help query` will need them offline), `Scope`. Done when every case in `expressions/` passes.

## Task 3: bases and query notes, and the docs

Files: `src/query/base.ts`, `src/query/query.ts`, `src/query/index.ts` (the public surface: `Properties`, `PropertyTypes`, `QueryNote`, `Evaluator`, `Base`, `Query`, `QueryError`, the value types), the runner's `bases/` and `queries/` parts (the `test.todo` placeholders gone; a check that every folder below `tests/query-conformance/` is one the runner knows), `test/query.base.test.ts` (node budget, anchor bomb, filter nesting), docs.

Port `Base.cs` (`parse(yaml)`, `viewNames`, `run(view, notes, self, now)`, stable sort, `KeyOrder`) and `Query.cs` (`read(note)`, `isBaseFile`, `isQuery`, `params`, `viewNames`, `run(view, args, notes, now)`, `check(now)`, the ```` ```base ```` blocks found as CommonMark fences, `params:` read from the frontmatter's YAML). Done when every case passes.

Docs in the same commit: `packages/eidolon-core/README.md` (a row for `src/query/` and a short section "Queries": what it is, the two dependencies and why); `tests/query-conformance/README.md` (the offline engine's runner `packages/eidolon-core/test/query.conformance.test.ts`, `pending` takes `cs` and `ts`); the spec's §7 and §9 (the TypeScript engine is built: where, with which YAML and regex engines and why; §9 no longer lists it); an ADR `docs/adr/0034-offline-queries-match-regular-expressions-in-linear-time.md` from `template.md` (decision: the offline engine matches with RE2 (`re2js`), as the server does with .NET's non-backtracking engine; why: patterns are anyone's input, a shared vault's query must not hang a reader's tab; consequence: no lookaround or backreferences on either side, the same subset), listed in `docs/adr/README.md`.
