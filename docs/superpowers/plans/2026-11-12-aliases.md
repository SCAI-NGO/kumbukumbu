# Aliases in the front matter: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `[[Kumbu]]` leads to a note whose front matter says `aliases: [Kumbu]`, everywhere links resolve, and unlinked mentions find a note by its aliases too.

**Architecture:** One parser (`NoteAliases`, on top of the hardened `Frontmatter.Read`) turns a note's content into its aliases; the one `LinkResolver` takes them as an optional constructor argument and tries them only after every name rule found nothing, marking such a resolution `ViaAlias`. Each caller that builds a resolver passes the aliases of the notes it already has (reading the vault's notes where it only listed paths); `mv` and `restore` key them through their path maps. `Mentions` learns to look for several terms.

**Tech Stack:** C# / .NET 10, xUnit (Microsoft.Testing.Platform), YamlDotNet 18.1 (already referenced). No web change.

**Spec:** `docs/superpowers/specs/2026-11-12-aliases-design.md`; brief: `docs/superpowers/overnighter/2026-11-12-aliases-brief.md`. Executors read both.

## Global Constraints

- British English in code, comments, docs, commit messages and user-visible text.
- No new NuGet or npm package. No new stored data, collection, index or cache.
- New C# files start with `// SPDX-License-Identifier: AGPL-3.0-or-later`; match the surrounding comment density.
- Only the exact top-level key `aliases`; `aliases:` with no value means none. The singular `alias:` is ignored.
- Every link that resolves today resolves to the same place afterwards; the alias step runs only when the name rules found nothing, only for a non-exact target without `/`, and never for a target ending in `.md`.
- `LinkKind` keeps its values. `LinkView`, `schema.d.ts`, the web app, `Publications.cs`, `AttachmentWriter.cs`, `FairCopies.cs`, `Auth/`, `Crypto/`, `Dav/`, sync and both CSPs stay untouched. `rm`'s message text stays as it is.
- The existing `WikiLink.Alias` is a link's *display text*; the new concept is named `NoteAliases` / `aliases` of a note, never plain `Alias`.
- Test data uses Alice, Bob, Carol and vaults like `Work`; no organisation names.
- Commits: imperative, no Conventional Commits prefix, end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; stage files by name. Never merge, tag, change the version or force-push.

## Review Focus

1. **Malformed front matter on a note anyone with write access can plant** (self-referencing anchor `a: &a [*a]`, anchor expansion, complex keys `[a]: 1`): measured on `f23d4ae`, `Frontmatter.Read` dies with a stack overflow on the first, takes 7 s on seven levels of tenfold expansion, and throws `ArgumentException` on the third. Every link resolution now parses such notes, so a request must get "no aliases", fast. Pinned in Task 1.
2. **A note named like another note's alias** (name beats alias): `[[Kumbu]]` must keep leading to `Kumbu.md`, never become ambiguous. Pinned in Task 3.
3. **`[[Kumbu.md]]`, `[[/Kumbu]]`, `[[./Kumbu]]`, `[[Work/Kumbu]]`** must not match by alias. Pinned in Task 3.
4. **Moving the aliased note** must leave `[[Kumbu]]` and `[[K²#Roadmap|roadmap]]` byte for byte. Pinned in Task 5.
5. **A short title with long aliases** (`K².md` with `aliases: [Kumbu]`) must still find "Kumbu" mentions. Pinned in Task 6.
