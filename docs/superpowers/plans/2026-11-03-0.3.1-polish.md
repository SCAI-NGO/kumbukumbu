# The polish for 0.3.1: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (or, if it is unavailable, emulate it with the plain Agent tool). One fresh subagent per task, then a spec-compliance review and a code-quality review, each by its own subagent. Subagents do red, green, commit and mutations; they never merge, push or switch branches. The controller pushes. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Six small changes that, with the console and the attachment wishes already on `master`, make Kumbu² 0.3.1.

**Architecture:** Five independent changes in the web app, the hub, the shell and the sharing events, and one concurrency change in `VaultCatalog`: a per-vault transition takes the place of holding the process-wide `_loading` across a re-keying's transactions.

**Tech stack:** .NET 10, minimal APIs, xUnit v3 on Microsoft.Testing.Platform, Testcontainers with MongoDB; React with Vite, TanStack Query, zustand, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-03-0.3.1-polish-design.md` ("spec §n"), reviewed and approved by the maintainer. Don't edit it. The maintainer decided that `history` hides nothing, since it has something of an audit log about it, and that a stored flag tells a restore (spec §5).

**Line anchors** are from `4dea582`. They may drift as you work; the sense counts.

## Global constraints

- Branch `feature/0-3-1-polish`. **Do not merge.** One **draft** pull request to `master`. No tags, no version change (`version.txt`, `src/Kumbu.Server/Kumbu.Server.csproj`, `web/package.json`), no pushes to `master`.
- British English in code, comments, docs, UI copy and commit messages. New C# and TypeScript files start with `// SPDX-License-Identifier: AGPL-3.0-or-later`. Match the surrounding naming, idiom and comment density; comments only where the reasoning isn't obvious.
- The repository names no organisation, customer or employer anywhere, tests and examples included. People: Alice, Bob, Carol. Vaults: `Gartenarbeit`, `Garten`, `Work`.
- Commit messages imperative and free-form ("Let a second tab follow a rename"), no Conventional Commits prefix, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `web/src/api/schema.d.ts` is edited **by hand**, as generated output would have it.
- Out of scope, whatever you find: pins, Options A and B, the owner lock-out in `PlantedUserSlotTests`, L1 of the rename's security review, the console's open decisions, the plugin's code (another repository).

## Review focus

Each has its test in the task that owns the code.

1. A second tab with unsaved text when the rename arrives: the text survives under the new path (Task 3).
2. A rename whose outcome isn't known: no `renamed` frame, and no tab moves (Task 3).
3. A revoked, an expired or an agent key, or a device key of another vault: not listed in the pairing dialog (Task 2).
4. A, B, A in one changeset, and a version restore: no `(restored)`. A restore, then a later write: one unmarked line (Task 4).
5. A caller cancelled while waiting for a transition, and a run that fails or is cancelled inside its transaction: nothing waits for ever (Task 6).

## How every task runs

1. **Red:** write the tests the task names; run only them. Expected: non-zero exit, the named tests failing for the reason the task gives. A compile error counts as red only for a member the task creates. "Zero tests ran" is a failure of the command, not red.
2. **Green:** the smallest change that passes; the task's command again. Expected: exit 0, 0 failed.
3. **Commit** locally, one commit per task.
4. **Mutations**, one at a time, those the task lists: make the breakage, run the task's command, see at least one test fail, restore with `git checkout -- <file>`. A mutation that survives means the test is too weak: strengthen it and say so in the report.
5. **Reviews, then push:** spec compliance, then code quality, each by its own subagent; fixes go back through 1 to 4; then the controller runs `git push -u origin feature/0-3-1-polish`.

Test filters are Microsoft.Testing.Platform's: `dotnet test --project tests/Kumbu.Server.Tests -- --filter-class "*Name"`, repeatable, ORed. `FullyQualifiedName~` doesn't work, and a glob in mid-name selects nothing. Web: `pnpm -C web test --run src/shell/ConnectObsidianDialog.test.tsx`.

**Full verification** at each phase gate (after Task 2, after Task 5, and in Task 7), all of it, as CI does. With your own MongoDB, give each run a fresh one (`docker rm -fv kumbu-test-mongo`).

Test fixtures: `tests/Kumbu.Server.Tests/KumbuAppFactory.cs` (`[Collection("app")]`, `app.PublicApi`), `tests/Kumbu.Server.Tests/Api/RestClient.cs` (`RestClient.NewAsync(app.PublicApi, vault: "Work")`, `CreateAsync`, `KeyAsync`, `SendAsync`, `GetAsync`, `JsonAsync`, `ErrorAsync`), `tests/Kumbu.Server.Tests/Sharing/Share.cs` (`ShareWithAsync`, `VaultIdAsync`).
