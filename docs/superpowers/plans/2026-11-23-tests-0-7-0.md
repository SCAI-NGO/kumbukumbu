# Plan: the specific test run of 0.7.0, with search by meaning on

Spec: `docs/superpowers/specs/2026-11-23-tests-0-7-0-design.md` (approved). Brief: `docs/superpowers/overnighter/2026-11-23-tests-0-7-0-brief.md`. Branch `feature/tests-0-7-0`, code under test `master` at `ad920a73`.

Execution: subagent-driven, in this session. One fresh implementer per task, then one fresh reviewer per task who checks each test against its feature spec; fix rounds resume the implementer, re-reviews until clean. The coordinator commits and pushes; subagents never commit, push, merge or switch branches.

## Rules for every task

These hold for every task below; each task repeats only what is particular to it.

- **Environment:** `export PATH=/opt/node26/bin:$PATH`; run from `/home/user/kumbukumbu/web`. One stack, the dev stack, runs during the writing tasks: the **search stack** (`E2E_SEARCH=1 E2E_PROXY_CA=/root/.ccr/ca-bundle.crt e2e/stack/up.sh`, then `pnpm exec playwright test --project=setup` once). Never start, stop or rebuild it from a subagent: ask the coordinator. A keep-alive outside the repository keeps the saved sessions from idling out.
- **Running tests while writing:** only your own tag, `--no-deps`, at most 2 workers, your own output folder:
  - MCP: `pnpm exec playwright test --no-deps --project=mcp --grep @tag --output /tmp/e2e-<tag>`
  - browser: `pnpm exec playwright test --no-deps --project=desktop --project=phone --grep @tag --output /tmp/e2e-<tag>`
  - serial: `pnpm exec playwright test --no-deps --workers=1 --project=serial --project=serial-phone --grep @tag --output /tmp/e2e-<tag>`
  - offline in Firefox: add `--project=offline-firefox`.
- **Tags:** the feature tag (`@similar`, `@synthesis`, `@graph`, `@overview`, `@devices`, `@sw`, `@offline`, `@tensorx`), plus `@search` on every test that needs search by meaning on, `@serial` for global lists and discreet vaults, `@phone` where the phone viewport is tested too. A new `@graph` test that does **not** carry `@search` also carries `@since-0-7-0`, so that `e2e:0.6.0`'s grep (which matches `@graph`) selects the same tests as before (Task 1). Never `@publish…` or `@windows` on the Published window's tests: they are `@overview` only.
- **Files:** each tag in its own spec files, `web/e2e/<tag>/<tag>.spec.ts` for the browser and `web/e2e/mcp/<tag>.spec.ts` for MCP (the `mcp` project matches `e2e/mcp/`). New files start with `// SPDX-License-Identifier: AGPL-3.0-or-later`, then a header comment: the feature spec's promises in scope, each with the test that covers it, or the reason it is left out (as `web/e2e/offline/offline.spec.ts` does).
- **Not touched:** anything under `src/`, `web/src/` and `web/sw/` apart from a `data-testid` where no role, label or text finds an element (tell the coordinator each one: file, line, why); `compose.yaml`, `compose.build.yaml`; the specs. No new dependency.
- **Test discipline:** no `waitForTimeout`, no fixed sleeps; locators by role, label or text; exact or structural assertions, never "contains no error" alone; a state read back through a second call. Every test is seen to fail once: break its key assertion, watch it fail, restore it; report the break per tag.
- **Meaning:** fixtures of clearly separated topics (below). Before asserting, run the fixture once and look at what arctic-m ranks; assert only order and membership of cases clear by meaning, never a score's value. A clear case that comes out wrong is run again on a fresh stack (ask the coordinator); if it stays wrong it is a finding marked **unclear**.
- **Waiting for embeddings:** only through the product's own signals (`semsearch`/`similar`'s "isn't indexed yet" and pending counts, `state: "preparing"` / `"unindexed"` of `/api/similar` and `/api/graph/similarity`), polled with `expect.poll(…, { timeout })` and a bound stated in the test: 3 minutes for the first index on a fresh stack (the model loads after the download), 60 seconds after that. Use the helper of Task 1 (`e2e/support/search.ts`).
- **Isolation:** each test in its own folder (`folder` fixture) under `Work`, or, where the feature's scope is a whole vault (Similar notes, the graph's suggestions, `similar` over every vault), in a vault of the spec file's own made in `beforeAll` and deleted in `afterAll` (deletion needs the password: `reservePassword`). Vault-wide answers are scoped to the folder or vault.
- **Rate limits:** every password check through `reservePassword(user)` (5 a minute per username), every PIN entry through `reservePin()`, every sign-in through `signIn`/`freshSession`. Hooks that make keys, shares or deletions get `test.setTimeout(240_000)` / `{ timeout: 240_000 }`.
- **Findings:** a bug gets `test.fail()` with an annotation `{ type: "finding", description: "F-xx: …" }` (UI) or `"M-xx: …"` (MCP) and its own assertion names it (`expect(x, "F-xx: …")`); the coordinator numbers them. Severity: High for data loss or a security breach (a read-only member writing, a discreet vault showing, a wiped copy opening, a changed file served), Medium for a feature not doing what its spec says, Low for wording, layout or a target under 44 px. A failure is run again alone first: passes → flaky, fix the waiting (never a retry); fails → bug, test or unclear.
- **Screenshots:** one per tag and viewport with `shot(page, testInfo, "<tag>")`, into `docs/superpowers/overnighter/2026-11-23-tests-0-7-0/` (`test.use({ shotsDir: shotsDir070 })`, Task 1). Never of a screen that shows a password, a key, a recovery key or a link with a code.
- **Secrets:** no password, PIN, key, invitation code, share link, recovery key or TensorX key in a log, an assertion message, a screenshot or a report. Pass answers holding links through `redact()` (`e2e/mcp/fixtures.ts`) before asserting.
- **Style:** British English; neutral names (Alice, Bob, `Home`, `Work`); match the suite's idiom (`support/test.ts`, `support/api.ts`).
- **Report back:** the files written, each test with the promise it covers, what is left out and why, the deliberate breaks and what they printed, the run's result (counts), candidate findings with steps, expected, actual, and `data-testid`s added.
