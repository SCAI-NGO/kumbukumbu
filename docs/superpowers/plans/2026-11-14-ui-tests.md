# End-to-end UI tests and the 0.5.0 specific run: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Playwright suite in `web/e2e/` that builds a stack from this checkout, sets it up through the app's public paths, tests the smoke set and every 0.5.0 checklist step a browser can test, and reports what it finds without fixing the product.

**Architecture:** `web/e2e/stack/run.sh` brings up the Compose project `kumbu-e2e` (local images, `pull_policy: build`), runs Playwright in two phases (`setup`+`desktop`+`phone`, then `serial`+`serial-phone` with `--no-deps`), and removes the stack with its volumes. The `setup` project makes Alice (bootstrap-admin's link) and Bob (her invitations) through the browser and the web app's API and saves their sessions in `web/e2e/.auth/`. Tests take `test`/`expect` from `web/e2e/support/test.ts`; each works in a folder of its own below `/Work/`.

**Tech Stack:** `@playwright/test` 1.63.0 (exact, dev dependency of `web/`), headless Chromium (pre-installed), Docker Compose 5.6.1 with buildx 0.38.1, Node 26.13.1 (`/opt/node26/bin`), pnpm 10.32.1.

**Spec:** `docs/superpowers/specs/2026-11-14-ui-tests-design.md`. **Brief:** `docs/superpowers/overnighter/2026-11-14-ui-tests-brief.md` (binding where it settles what the spec leaves open).

## Global Constraints

- The run **reports, it doesn't fix**. A test that finds a real bug stays, with `test.fail(true, "F-NN …")` placed first in the test body and `test.info().annotations.push({ type: "finding", description: "F-NN" })`. On one viewport only: `test.fail(onPhone(testInfo), …)` or `test.fail(!onPhone(testInfo), …)` (`onPhone` covers `phone` and `serial-phone`). Finding ids are given out by the controller; a subagent uses `F-??` and says so.
- No change under `src/` or `web/src/` except `data-testid` attributes, and only where no role, label or text finds the element; each is reported. `compose.yaml`, `compose.build.yaml`, `Dockerfile`, the specs and `web/src/api/schema.d.ts` stay as they are.
- Locators by role, label or text. **No `waitForTimeout`.** `retries: 0` stays. A test is done only after it was seen to fail once (a deliberate break, then restored).
- Titles: `<source> #<step>: <what passes> @<tag>`, e.g. `calendar #7: What's on lists the open tasks with a calm span @calendar @serial @phone`. Exactly one feature tag (`@smoke`, `@calendar`, `@flags`, `@explorer`, `@recent`, `@mermaid`, `@embeds`, `@blockrefs`, `@mentions`, `@aliases`, `@ailink`, `@photo`), plus `@phone` to run it again at 375 px (dark, touch), plus `@serial` for tests that assert a list across vaults or folders (What's on, its badge, Recent changes, Last changed's order, the vault list, the server log) or touch discreet state.
- Isolation: every test writes only below `/Work/${folder}/` (the `folder` fixture: source, step, project and a random part) and asserts relative to that folder. Fixtures of a tag live in `web/e2e/fixtures/tags/<tag>/…` and are copied with `seedAs("tags/<tag>/…", \`/Work/${folder}/…\`)`; only `fixtures/Home` and `fixtures/Work` are seeded by the setup. Dated fixture notes use `{{today}}`, `{{today+N}}`, `{{today-N}}` (days, Vienna), replaced when seeded. A test that leaves something vault-wide behind (an alias, an unreadable date, a day note, a publication) removes it at its end.
- Discreet steps: `@serial`, in a session of its own (`const { page } = await freshSession("alice")`), revealing with `revealDiscreet(page)` (phone: open the tree drawer first), ending with `hideDiscreet(page)`. Never sign out of the shared saved session. At most two PIN entries per test. The ledgers in `support/session.ts` keep sign-ins and PIN entries under 5 a minute; `freshSession` extends the test's timeout for it.
- Dates: `support/time.ts` (`today()`, `nowTime()`, `addDays`, `addMonths`, `addYears`, `isoWeek`, `monday`, `format`), Europe/Vienna, never fixed dates. `page.clock` only where the server's time doesn't matter; each use is reported.
- Agent steps: reading commands through `aliceApi.console(cmd)` (the web console's API); writing ones (`calendar set/close/…`, `mv`, `write`, `publish add`, `rm`) through `mcp.sh(cmd)` or `mcp.call(tool, args)` (a key of Alice's with write on `Work`; Home is hidden in her shared session).
- Steps needing a device, Carol or Dana, Bob as a write member, deactivating Alice, a restart, or an hour passing are left out and listed with the reason. No new users, roles or stack phases.
- No secret (password, PIN, key, recovery key, invitation code, `/s#…` secret, AI link token) in a log line, assertion message, `console.log`, screenshot or the report. Assert on the shape of a link (regex) without printing it; take screenshots only where no secret shows.
- Screenshots into `docs/superpowers/overnighter/2026-11-14-ui-tests-0.5.0/`: `shot(page, testInfo, "<tag>")` once per tag per viewport; a finding's (`F-NN-<project>.png`) is taken automatically of Alice's `page` when a finding's test fails as expected; for a finding seen on another page, call `shot(thatPage, testInfo, "F-NN")` before the failing assertion.
- On the phone, the install hint ("Install Kumbu² as an app") may cover controls: dismiss it with **Not now**, as a person would.
- British English; new `.ts` files and shell scripts start with the SPDX line. Neutral names only.
- Subagents never commit, push, merge, switch branches, start or stop the stack, or run the `setup` project. The controller brings the stack up, runs the setup once, commits by name, and pushes to `feature/ui-tests-0-5-0` only.

## Shared interfaces (Task 0; every task consumes them)

- `web/e2e/support/test.ts`: `test`, `expect`, `onPhone(testInfo)`, `shot(page, testInfo, name)`, `fixtureTree(from, to)`. Fixtures: `page` (Alice's saved session), `bobPage` (Bob's, this project's viewport and scheme), `aliceApi: Api`, `bobApi: Api`, `folder: string`, `seedAs(from, to): Promise<string[]>`, `freshSession(user): Promise<{ context; page }>`, `projectContextOptions` (for a reader context without a session: `browser.newContext(projectContextOptions)`), worker `mcp: Mcp`.
- `web/e2e/support/api.ts`: `Api.as(user)`, `Api.anonymous()`, `api.getNote(path): Promise<{ path; content; version }>`, `api.putNote(path, content)`, `api.putFile(path, bytes)`, `api.deleteNote(path)`, `api.history(path)`, `api.console(cmd): Promise<{ text; isError }>`, `api.json<T>(method, url, data?)`, `api.confirmPassword()`, `withDates(text)`; `mcp.sh(cmd)`, `mcp.call(tool, args): Promise<{ text; isError }>`.
- `web/e2e/support/session.ts`: `signIn(page, user)`, `revealDiscreet(page)`, `enterPin(page)`, `hideDiscreet(page)`.
- `web/e2e/support/env.ts`: `secrets()`, `baseURL`, `storageState(user)`, `stackDir`.
- Projects: `setup` → `desktop` (1280, light, all but `@serial`) and `phone` (375, dark, touch, `@phone` but not `@serial`) → `serial` (desktop, 1 worker) → `serial-phone`.

## How a tag task runs its tests (each task repeats the commands)

The controller has the stack up (`E2E_PROXY_CA=/root/.ccr/ca-bundle.crt web/e2e/stack/up.sh`) and ran `pnpm exec playwright test --project=setup` once. Subagents run only with `--no-deps`, from `/home/user/kumbukumbu/web` with `PATH=/opt/node26/bin:$PATH`.

## Review Focus

- A finding on one viewport marked on both: `onPhone(testInfo)` decides.
- A list across vaults asserted outside `@serial`: passes alone, flakes in the full run.
- A test asserting less than the checklist's "Passes if" (e.g. that a menu opens, not its eight items). Each task's review compares assertions with the checklist.
- Times near midnight in Vienna: a test that places entries at now ± hours skips itself with a reason when they would cross midnight (`test.skip(cond, "…")`), and the report lists it.
- Secrets in output: no assertion on an element that shows a secret; the setup takes no screenshots.
