# The fixes for 0.3.0: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (or, if it is unavailable, emulate it with the plain Agent tool). One fresh subagent per task, then a spec-compliance review and a code-quality review. Subagents do steps 1 to 4 of a task and never merge, push or switch branches. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close the security findings of two independent reviews and the gaps the hand test of vault sharing found, so that 0.3.0 can be released.

**Architecture:** Changes to the existing ASP.NET Core server (`src/Kumbu.Server`, `src/Kumbu.Core`), the PDF sidecar's client and the React web app (`web/`). No change to pins, slots, re-keying's transactions or `_loading`, which wait for 0.3.1.

**Tech stack:** .NET 10, minimal APIs, MongoDB transactions, xUnit v3 with `FakeTimeProvider` and Testcontainers; React with Vite, TanStack Query, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-01-0.3.0-fixes-design.md` (binding; "spec §n" below). Background: `docs/superpowers/specs/2026-10-31-collab-design.md` ("design §n"), `docs/security-architecture.md`.

## Global constraints

- Branch `feature/0.3.0-fixes`. **Do not merge.** One **draft** pull request to `master`. No tags, no version bumps (`version.txt`, `src/Kumbu.Server/Kumbu.Server.csproj`, `web/package.json`), no pushes to `master`.
- British English in code, comments, docs, UI copy and commit messages. `// SPDX-License-Identifier: AGPL-3.0-or-later` on new C# and TypeScript files. Match the surrounding naming, idiom and comment density; comments only where the reasoning isn't obvious.
- No organisation, customer or employer names anywhere. People: Alice (owner), Bob and Carol (members). Vaults: `Gartenarbeit`, `Work`.
- No secrets in logs, assertions, test data or the report.
- Commit messages imperative and free-form ("Refuse redirects from the sidecar"), no Conventional Commits prefix, ending with the session's attribution lines.
- Commit messages and the PR describe the fixes plainly and don't spell out how to attack a deployed `0.2.3`.
- `web/src/api/schema.d.ts` is generated and never edited by hand. After a task that changes REST shapes, regenerate it:

## How every task runs

1. **Red:** write the tests the task names; run only them with the task's command. **Expected:** a non-zero exit with only the named tests failing, for the reason the task gives (a compile error counts as red only for a type or member the task creates). "Zero tests ran" is a failure of the command, not red.
2. **Green:** the smallest change that passes; then the same command. **Expected:** exit 0, 0 failed.
3. **Commit** locally.
4. **Mutations**, one at a time: make the breakage the task names, run its command, see at least one test fail, restore with `git checkout -- <file>`. A mutation that survives means the test is too weak: strengthen it and say so in the report.
5. **Reviews, then push:** a spec-compliance review and a code-quality review by their own subagents; fixes go back through steps 1 to 4; then the controller, not a subagent, runs `git push -u origin feature/0.3.0-fixes`.

Test filters are Microsoft.Testing.Platform's: `--filter-class "*Name"`, repeatable, ORed. `FullyQualifiedName~` doesn't work here, and a glob in mid-name selects nothing. `--project` runs one test project.

**Full verification** at each phase end, all of them, whatever the phase touched, as CI does. Give each run a fresh MongoDB if you run your own (`docker rm -fv kumbu-test-mongo`).

```sh
dotnet restore --locked-mode
dotnet build --configuration Release --no-restore
dotnet test --configuration Release --no-build
pnpm -C web install --frozen-lockfile && pnpm -C web test --run && pnpm -C web build
pnpm -C pdf install --frozen-lockfile && pnpm -C pdf test && pnpm -C pdf build
```

Test fixtures: `tests/Kumbu.Server.Tests/KumbuAppFactory.cs` (`[Collection("app")]`, `app.PublicApi`, `app.Database`), `tests/Kumbu.Server.Tests/Api/RestClient.cs` (`RestClient.NewAsync(app.PublicApi, vault: "Gartenarbeit")`), `tests/Kumbu.Server.Tests/Sharing/Share.cs` (`RestClient.ShareWithAsync`, `Share.GrantAsync`), `tests/Kumbu.Server.Tests/Vaults/VaultFixture.cs` (`VaultWorld`), timed tests as in `tests/Kumbu.Server.Tests/Api/PasswordWindowTests.cs:34-40`, Core in `tests/Kumbu.Core.Tests/Fakes/`.

## Review focus

1. A member who renames in a loop while a run is under way, and an unrelated user meanwhile: pinned in Task 1.8.
2. A second invitation link pasted over a refused one in the same tab, and an old secret left in session storage: pinned in Task 3.1.
3. A password manager filling every dialog with a text field before a password, not only the share dialog: Task 3.2 checks all of them.
4. A note created in `Board` by a member with only `write`, and a note with a card's frontmatter already: pinned in Task 3.6.
5. A consent decision or a pairing code from a session that isn't the current one: pinned in Tasks 1.3 and 1.7.
