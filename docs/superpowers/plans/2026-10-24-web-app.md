# Web App (step 9a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The mobile-first web app for Kumbu²: join, sign in, vaults, tree, reading and editing notes, search, Markdown upload, API keys, settings and admin — served by the server itself.

**Architecture:** A React single-page app in `web/`, built by Vite into `web/dist`, copied into the server image and served by ASP.NET from `wwwroot` with a fallback to `index.html` for every path outside `/api` and `/mcp`. It talks only to the REST API of the accounts plan (`/api`, same origin, session cookie). Types come from the server's OpenAPI document. Look and interactions follow `concepts/MOBILE_EDITOR_v1.md` and its clickable prototype; where they differ from the concept, the concept wins (see that file's header).

**Tech Stack:** TypeScript, React 18.3, Vite 6, Tailwind v4 (`@tailwindcss/vite`, `@theme` tokens), react-router-dom 6, TanStack Query 5, zustand 5, react-markdown 10 + remark-gfm 4, lucide-react, qrcode 1.5, `openapi-typescript` + `openapi-fetch`; Vitest 2 + Testing Library + jsdom; pnpm 9. IBM Plex Sans and Mono, self-hosted (`@fontsource/ibm-plex-sans`, `@fontsource/ibm-plex-mono`).

**Spec:** `docs/superpowers/specs/2026-10-24-accounts-and-web-design.md` §4 (screens, upload, keys), `concepts/MOBILE_EDITOR_v1.md` (look, layout, interactions, colour schemes), the accounts plan `docs/superpowers/plans/2026-10-24-accounts-backend.md` Tasks 8–9 (the endpoints).

## Global Constraints

- British English in code, comments and UI text; UI copy short and plain. SPDX `// SPDX-License-Identifier: AGPL-3.0-or-later` on new files.
- Code taken over from chatsundere (allowed by Chris, its author, under AGPL-3.0-or-later) keeps a line `// Adapted from chatsundere (<path>)` under the SPDX header.
- Mobile first at 390×844; it must also work on a laptop window. Touch targets ≥ 44 px; text contrast ≥ 4.5:1; `prefers-reduced-motion` respected; 16 px editor font (no iOS zoom).
- Colour schemes as tokens (`bg`, `surface`, `surface-2`, `line`, `text`, `text-body`, `muted`, `dim`, `accent`, `accent-text`, `on-accent`): for this step **Kumbu** (the spec's values) and **Catppuccin Latte** adjusted to 4.5:1 per the spec's rules; a unit test checks every scheme's text tokens against `bg`, `surface`, `surface-2`.
- No offline cache, no service worker (concept: no plaintext on the device).
- Never store secrets in `localStorage`; the session lives in the `HttpOnly` cookie only. API keys and recovery keys are shown once and kept only in component state.
- All requests same-origin with `credentials: "include"`; a 401 sends to sign-in.
- `pnpm -C web test` and `pnpm -C web build` green after every task; `dotnet test` stays green.

## Review Focus

1. The editor saves while the user types and an agent writes the same note: the 409 toast appears, nothing is overwritten silently, and "keep mine" saves on top of the newer version only after the user chose it. Test in Task 5.
2. A folder upload of an Obsidian vault with `.obsidian/`, images and nested folders, some notes already present: nothing is written before the user decides about conflicts; non-Markdown is listed as skipped; progress shows per batch. Test in Task 7.
3. A recovery key or new API key on screen: leaving the page without having copied or downloaded it asks once; it never reaches storage, logs or the URL. Test in Tasks 2 and 8.
4. A wiki link to a note in another vault, or an ambiguous one: shown as the `links` command resolves it (missing = dashed; ambiguous = marked), never resolved across vaults. Test in Task 4.
5. A session that ends mid-use (timeout, signed out elsewhere): the next request lands on sign-in with a short message, and returns to the same note after signing in. Test in Task 2.
