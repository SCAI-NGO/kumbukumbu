# Activity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A vault's changesets in one view (who, when, which files changed, were added, renamed or deleted), each file comparable side by side with the version before or with today's text, plus a search switch that finds words in earlier versions.

**Architecture:** Moves and trash records learn the changeset of the write that made them (additive, sealed as today). A pure Core function folds a vault's note states, trash and move records into changeset rows; a session-only endpoint serves them with writer kinds. The web app shows them in a sheet from the vault menu, next to Trash and Checkpoints, and compares versions with the existing `lineDiff`. Earlier-version search is a separate, words-only endpoint over the history in memory.

**Tech Stack:** .NET 10, xUnit, MongoDB (test fixture), React + TypeScript, TanStack Query, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-demo-round-design.md` §4 (binding); writer kinds from `docs/superpowers/specs/2026-10-26-obsidian-sync-design.md` §5a.

## Global Constraints

- Sessions only, the owner's vaults: both new endpoints carry `SessionOnlyMetadata`; API keys, connections and the dev token get `403`.
- A changeset is what one writer did with gaps under 10 minutes, for an hour at most (`Changeset.Idle`, `Changeset.MaxLength`); unchanged by this plan.
- Limits as stored: 10 versions per note (`NoteWriter.HistoryLimit`), trash and move records 30 days.
- Copy (exact): menu entry `Activity`; sheet title `Activity`; limit line `Older changes may be incomplete: Kumbu² keeps the last 10 versions of each note.`; empty state `No changes yet.`; toggle labels `Against the version before` / `Against now`; search switch `Include earlier versions`; earlier-hit label `Earlier version · <time>`.
- Writer wording: kind `user` → `You`; `device` → `You in Obsidian (<device>)` (the part of the key name after `Obsidian `); `agent` → `Agent <name>`; `server` or `null` → the writer label as is.
- Earlier-version search: words only (no embeddings), every query word in the section, case-insensitive.
- British English in code, comments and copy; the repo's comment density.

## Review Focus

1. **A note edited and renamed in one changeset** must show as one file, `renamed (old → new)` and changed, not as two files. Test in Task 2 (`An_edit_and_a_rename_in_one_changeset_are_one_file`).
2. **A note edited in a changeset and deleted later** keeps that changeset's edit visible (its states live in the trashed note). Test in Task 2 (`Edits_of_a_note_deleted_later_still_show`).
3. **Deletions in a session without any other write** belong to one changeset, not one each: the writer's open changeset is also found from their moves and trash records. Test in Task 1 (`Removing_two_notes_in_a_row_is_one_changeset`).
4. **An old version whose section is unchanged today** is not an earlier-version hit, so the switch never repeats today's results. Test in Task 5 (`A_section_unchanged_today_is_no_earlier_hit`).
5. **Another user's session or an API key** never sees a vault's activity or old versions. Tests in Task 3 (`An_api_key_gets_403`, `Another_users_vault_is_404`) and Task 5 (`Earlier_search_is_sessions_only`).

### Task 2: Changesets of a vault, folded in Core

**Files:**
- Create: `src/Kumbu.Core/Notes/Activity.cs`
- Test: `tests/Kumbu.Core.Tests/Notes/ActivityTests.cs`

**Interfaces:**
- Consumes: Task 1's records; `StoredNote.History`, `NoteWriter.HistoryLimit`.
- Produces:
  ```csharp
  public enum ActivityFileKind { Added, Changed, Renamed, Deleted }
  /// Version: the state this changeset left (null for Deleted); Before: the state before it (null: none, or no longer kept).
  public sealed record ActivityFile(string Path, ActivityFileKind Kind, string? From, string? Version, string? Before, bool BeforeLost, bool Trashed);
  /// Id null for a write that joins no changeset (restore, seed) or a move/removal recorded before Task 1.
  public sealed record ActivityRow(string? Id, string Writer, DateTime From, DateTime To, IReadOnlyList<ActivityFile> Files);
  public static class Activity
  {
      public static IReadOnlyList<ActivityRow> Rows(IReadOnlyList<StoredNote> notes, IReadOnlyList<TrashedNote> trash, IReadOnlyList<MoveRecord> moves, DateTime? before, int limit);
  }
  ```

Behaviour: every state of every note (current and history) and of every trashed note, plus every move and trash record, grouped by changeset id; states without an id are rows of their own. `Writer` is `Writers.Identity` of the label. `From`/`To` are the earliest and latest time in the group. Per path in a row one file: a move record → `Renamed` with `From`; a trash record → `Deleted` (`Trashed: true`); a state with a predecessor state → `Changed` (`Before` = predecessor's version); the oldest state of a note whose history is below `HistoryLimit` → `Added`; the oldest state of a full history → `Changed` with `BeforeLost: true`. A path that is renamed and edited in one row is one `Renamed` file with `Version` and `Before` set. `Path` is the note's path now (history moves with the note); for a trashed note, its path when deleted. Rows newest first by `To`; `before` keeps rows with `To < before`; at most `limit` rows. Files within a row in text order.

  - `A_restore_is_a_row_of_its_own`: a state with `Changeset == null` → a row with `Id == null`.
  - `Rows_are_newest_first_and_paged_by_before`: three rows; `limit: 2` gives the two newest; `before` = the second row's `To` gives the third.
