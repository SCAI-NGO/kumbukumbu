# The calendar: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every note with a time in its frontmatter (or a date as its name) shows in a per-vault calendar, in What's on and in a badge, for people in the web app and for agents through `sh calendar`.

**Architecture:** All rules of spec §2–§5 live in Core (`src/Kumbu.Core/Calendar/`): values, one entry reader, states, the layout of a week or month, What's on, and one write service that `sh calendar` and the REST endpoints share. The server adds the caller's zone, the per-user calendar settings (zone plain, view state sealed per vault id) and `CalendarApi`. The web app adds `web/src/calendar/` (pages, dialogs, header line, badge). Notes are read on demand; no index, no stored copy of entries.

**Tech stack:** C# / .NET 10 (`TimeZoneInfo` with IANA ids, `System.Globalization.ISOWeek`), YamlDotNet through `Frontmatter`, xUnit v3 with `FakeTimeProvider`; React, TanStack Query, openapi-fetch, Vitest; MongoDB. No new package.

**Spec:** `docs/superpowers/specs/2026-11-12-calendar-design.md` (approved; do not change). Brief: `docs/superpowers/overnighter/2026-11-13-calendar-brief.md`.

## Global constraints

- No new npm or NuGet package. Time zones from `TimeZoneInfo` (IANA ids) and `Intl`; ISO weeks from `System.Globalization.ISOWeek`.
- British English everywhere; the UI is English (no localisation): "Week 46", never "KW 46".
- New C# and TypeScript files start with `// SPDX-License-Identifier: AGPL-3.0-or-later`.
- No employer, customer or workplace names; use Alice, Bob, Dana, `Home`, `Work`, `Tagebuch`.
- The web app never says "problems": it says **Dates I couldn't read**. Agents' output says "Problems".
- Spec wording is used verbatim where it gives it: "Nothing this week yet. Tap a day to add something, or give any note a day from its ⋯ menu. Your AI can do it too: \"put this on Friday\".", "Nothing on. Enjoy it.", "Closed · Undo · Add a reason", "Add to calendar…", "Edit date…", "Remove from calendar", "To do", "Show early: … before", "Later", "+1 day", "+1 week", "Pick a date…", "Postpone", "More time", "Also ongoing (N)", "Show grid", "Today", "This week", "This is the day note of 12 November (by its name)", "Move to Done".
- Writes: frontmatter keys changed through `Frontmatter.Set` only; every other byte stays; written values unquoted in the forms `2026-11-20`, `2026-11-20T14:00`, `2026-W47`, `7d`; key order `when, until, task, closed, reason, upcoming, tz` for new keys, after existing keys.
- Every write goes through `NoteWriter` (`WriteAsync` with the version just read; retry on conflict up to 3 times) with the caller's rights, leaving a version.
- Board: unchanged. On a card `close`, `reopen`, `move` and `set` (except `--upcoming`) refuse naming the board tool; Later on a card goes through `BoardService.UpdateAsync` (its `due`).
- Time in tests only from `FakeTimeProvider` / an injected `Func<DateTime>`; never the wall clock.
- Not touched: `Auth/`, `CallerMiddleware`, `Crypto/`, sharing and roles, publishing, `Dav/`, sync, OAuth, `Security.cs` CSPs, `UserKeyRotation`.

## Review focus

1. **A day note named by date in a deep sub-folder and also with a different `when`**: the `when` wins, the entry shows once (Task 2 test `When_in_the_frontmatter_wins_over_the_name`).
2. **A timed entry across the spring-forward gap in `Europe/Vienna`** (`2026-03-29T02:30`, a local time that does not exist): it is read, not dropped; it maps to 03:30 local (Task 3 test `A_time_in_the_spring_gap_is_read_as_the_hour_after`).
3. **The same note read by two users in different zones**: a day entry is the same day for both; a timed one is "ongoing" for one and "upcoming" for the other (Task 3 test `The_same_instant_for_two_zones`).
4. **Frontmatter with CRLF, comments and quoted keys**: `calendar set` keeps every other byte (Task 6 test `Set_keeps_every_other_byte`).
5. **A discreet vault hidden in the web session**: What's on, its count and its colour are byte-for-byte the same as with no entries in that vault (Task 8 test `Whats_on_says_nothing_of_a_hidden_vault`).

public enum EntryState { NotYet, Upcoming, Ongoing, Overdue, Done, Past }
public sealed record EntryStatus(EntryState State, string? Span);   // Span: "in 7 days", "until Fri", "1 day"; null for NotYet, Done, Past
public static class EntryStates
{

    public static EntryStatus Of(Entry entry, DateTime nowUtc, TimeZoneInfo zone);
    public static DateTime OngoingFromUtc(Entry entry, TimeZoneInfo zone);  // start of When's first day (a Time: start of its day; a Time with until: the time)
