A fresh subagent reviewed this plan against the spec, the brief and the code. Each finding below **overrides** the task text it names; every implementer reads this section first.

## Task 8: Frontmatter text functions (§2.2), pure

**Files.** New `web/src/note/frontmatterText.ts` and `web/src/note/frontmatterText.test.ts`. Nothing else.

**API.**
- `findPropertyBlocks(content: string): { start: number; end: number; keys: string[] }[]`: 0-based line indexes of the opening and closing `---` in the note's text. Rules: lines split on `\n` (a trailing `\r` ignored for the checks); the note's own frontmatter (as `splitFrontmatter` finds it) and fenced code (``` and `~~~`, by CommonMark's fence rules: same character, at least as long, up to three spaces of indent) are skipped; the opening line is exactly `---`, not line 0, and the line before it is blank or an ATX heading (so it renders as a rule, not as a setext underline under prose); then one or more lines, none blank, that `parseProperties` reads, each top-level key a plain key (`^[A-Za-z][A-Za-z0-9_-]*$`), `- item` lines allowed only under a `key:`; then a line exactly `---`. A block that fails any rule gives no hint. Scanning continues after a block's closing line.
- `moveToProperties(content: string, block: { start: number; end: number }): { content: string } | { refused: "exists"; key: string } | { refused: "unreadable" } | { refused: "gone" }`: re-finds the block in `content` (`gone` when it is no longer a block there); refuses `unreadable` when the note's frontmatter exists and `parseProperties` returns null; refuses `exists` with the first key already in the frontmatter; else removes the block's lines (their bytes and terminators exactly) and inserts the key lines before the frontmatter's closing line, or creates `---`, the lines, `---` at the very top. Line endings: inserted lines take the frontmatter's (its opening line's) ending; a created frontmatter takes the ending of the note's first line, `\n` when it has none.
- `addProperty(content: string, name: string, value: string): { content: string } | { refused: "name" } | { refused: "exists" } | { refused: "unreadable" }`: `name` must match `^[A-Za-z][A-Za-z0-9_-]*$` (else `name`); exists → `exists` (case-sensitive, as YAML keys are); writes `name: <yamlValue(value)>` as the frontmatter's last line, or creates the frontmatter.
- `yamlValue(value: string): string`: plain when `^[A-Za-z_][A-Za-z0-9 _./-]*$`, not ending in a space, and not (case-insensitively) `true false yes no on off null ~`; else `"…"` with `\` → `\\` and `"` → `\"`; empty → `""`. A value with a line break is quoted with the break as `\n` (no block text).

**Tests (red first)** `frontmatterText.test.ts`, tables:
- detection: Chris's case `# aliastest\n---\naliases: [kumbu]\n---\n` → one block; a rule alone; `prose\n---\nkey: v\n---` (setext over prose) → none; inside ``` and `~~~` fences → none; a line `key: |` → none; a blank line inside → none; `Buy milk: today` (a key with a space, not a plain key) → none; two blocks → two; `key:` with `- a` lines → one; the real frontmatter alone → none; CRLF note → found.
- move: no frontmatter → created at the top (the §3 example: `# Standup\n---\naliases: [daily]\n---\n` → `---\naliases: [daily]\n---\n# Standup\n`); with frontmatter → appended before its `---`; existing key → `exists` naming it; unreadable frontmatter → refused; CRLF throughout → CRLF kept; frontmatter whose closing `---` has no final newline; empty frontmatter `---\n---\n`; body starting with a blank line; block at the end without a final newline; every byte outside the block unchanged (asserted by comparing the result with the expected string exactly).
- add: the same layouts; refusals; `yamlValue` table: `Alice` plain, `Alice Smith` plain, `2026-11-15` quoted, `-x` quoted, `true`/`No`/`NULL`/`~` quoted, `a: b` quoted, `say "hi"` → `"say \"hi\""`, `back\slash` → `"back\\slash"`, `` → `""`, `a/b.c_d-e` plain, `#tag` quoted.

Run: `pnpm -C web test --run src/note/frontmatterText.test.ts`.
