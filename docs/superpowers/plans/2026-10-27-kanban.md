# Kanban Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One board per vault: cards are notes in `/Board/`, placed by frontmatter, read with `board` in `sh`, changed atomically with the MCP tool `board` and the web app.

**Architecture:** Everything board-specific lives in `src/Kumbu.Core/Board/`: a frontmatter reader and surgical writer, ranks, the board definition, a pure `BoardReader` over `INoteReader` (so checkpoints work for free) and a `BoardService` for the writes on `INoteStore`, `NoteWriter` and `NoteMover`. The server adds thin adapters (MCP tool, REST endpoints); the web app adds one route.

**Tech Stack:** .NET 10 / C# (xUnit), YamlDotNet (new, `Kumbu.Core`), React + TypeScript + Tailwind (Vitest), pnpm.

**Spec:** `docs/superpowers/specs/2026-10-27-kanban-design.md`

## Global Constraints

- Code, comments, docs, commits: British English. Source files start with `// SPDX-License-Identifier: AGPL-3.0-or-later`. No organisation names anywhere; examples use "Work" or "Kumbu²".
- Board folder `/<Vault>/Board/`, definition `/<Vault>/Board/Board.md`, archive `/<Vault>/Board/Archive/`.
- `Board.md` frontmatter: `kumbu-board: 1`, `columns` (name or `Name: [flags]`, flags `archivable`, `reason`), `archive: { after: 30, minDays: 14 }` (those defaults when missing). Column names unique ignoring case, 1 to 64 characters, no `/`.
- Card keys the server owns: `column`, `rank`, `due` (`YYYY-MM-DD`), `tags` (list), `moved` (column name → `YYYY-MM-DD`), `reason`, `archived` (`YYYY-MM-DD`). Dates are UTC days from `TimeProvider`.
- Ranks: characters `0-9A-Za-z`, ordinal comparison; re-rank a column when a new key would be longer than 24 characters.
- `board` reader: 20 titles per column, then a hint; archivable columns show only their count unless `--column` names them.
- `position`: `top`, `bottom` (default), `before:<card>`, `after:<card>`.
- A move or update never changes a card's text and takes no version token; it never rewrites frontmatter lines it doesn't own.
- Adding YamlDotNet changes `packages.lock.json` of Core, Server and both test projects: `dotnet restore Kumbu.slnx --force-evaluate`, commit all lock files.
- Build and test: `dotnet test --solution Kumbu.slnx`; `pnpm -C web test --run`; `pnpm -C web build`.

## Review Focus

- A card's frontmatter holds the user's own properties, comments and odd spacing (Obsidian writes `tags:` as a block list): a move keeps every other line byte for byte. Test in Task 1.
- Column names written in another case in a card (`column: doing`) count as the column; the card's `moved` keys keep the board's spelling. Test in Task 3.
- A hand-edited `Board.md` with malformed YAML, a duplicate column or an unknown `kumbu-board` version: `board` says what is wrong and the write tool refuses, nothing guesses. Test in Task 3 and Task 5.
- The card changes between the server's read and its write (Obsidian syncs a text edit): the move retries on the new state and keeps the new text. Test in Task 4.
- A card title that can't be a note name (`a/b`, `CON`, a trailing dot) or exists already: `add` fails with the note-name message, no file. Test in Task 4.
