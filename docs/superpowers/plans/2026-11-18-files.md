# Files Implementation Plan

> Execute task by task, subagent-driven: one implementer per task (or per small group), a review after each, a whole-branch review at the end of each pull request. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every file type as an attachment (PR 1), and files larger than 15 MB in chunks (PR 2).

**Spec:** `docs/superpowers/specs/2026-11-18-files-design.md` (read it first; decision numbers below refer to it).

**Tech stack:** C# / .NET 10, MongoDB, xUnit (server and core); React 19, TypeScript, Vitest (web).

## Global constraints

- British English in code, comments, messages and docs; `// SPDX-License-Identifier: AGPL-3.0-or-later` at the top of every new source file; match the surrounding comment density and idiom.
- **Test first:** a failing test before each task's code; run it, see it fail for the right reason, then implement.
- **Hard (security):** a file of kind `file` is never served inline or as a type a browser renders as a document (decision 4). XML is never parsed with DTD processing. Chunks are sealed with the context of decision 10; no partial file is ever visible.
- **Hard (data):** existing blobs, records and their history keep working unchanged; no migration.
- **Soft:** where a soft constraint makes a fix many times bigger, stop and say so rather than building around it.
- Stay in track B's area: `src/`, `tests/`, and in `web/` only `api/`, `upload/`, `attachments/` and the small fallbacks named in the tasks. Track A owns the editor and layout.
- Tests: `dotnet test --solution Kumbu.slnx --filter <namespace or class>` while iterating, with `KUMBU_TEST_MONGO=mongodb://127.0.0.1:27017/?replicaSet=rs0&directConnection=true`; the whole server suite once per pull request (~20 min). Web: `pnpm -C web test --run <path>`, then `pnpm -C web test --run` and `pnpm -C web build`.
- Commits: imperative, free-form, ending with the session's attribution lines.

## Review focus

1. A folder with a dot in its name (`/Work/v1.2/`) and a file without an extension (`/Work/Makefile`) side by side: `ls`, `cat`, `mv`, `rm`, `restore`, links, the tree and `PROPFIND` treat each as what it is.
2. A file where a folder is, and a folder (or a note below it) where a file is: refused, both ways, through every way in.
3. An `.html` file from every endpoint: `attachment`, never `text/html`, `nosniff`, the sandbox policy.
4. A large upload that stops half way, or hits the quota half way: no head, its chunks swept, the quota given back.
5. Re-keying a vault with a large file: the file opens afterwards, its chunks untouched, its blob id new.
