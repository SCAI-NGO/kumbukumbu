# WebDAV access, storage quota, access tabs — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user mount Kumbu² as a drive over WebDAV with per-vault shares, under a storage quota enforced on every write path, with `df`/`du`, emptying the trash and an access page in three tabs.

**Architecture:** A share is built like an API key: a `dav_shares` collection beside `api_keys`, `dav` slots beside `key` slots, a `DavShareCredential` beside `ApiKeyCredential`, resolved by `CallerMiddleware` from HTTP Basic on `/dav` only. The WebDAV protocol is hand-written in `src/Kumbu.Server/Dav/` on top of the per-request `EncryptedNoteStore`, `NoteWriter`, `AttachmentWriter` and `NoteMover`, with an in-memory parking area for client junk. The quota is one check inside `EncryptedNoteStore`'s writing methods, against a per-owner usage cache computed with `Admin.BytesByVaultAsync`'s aggregation.

**Tech Stack:** C# / .NET 10, ASP.NET Core minimal APIs, MongoDB driver, xUnit v3 on Microsoft.Testing.Platform, React + Vite + Vitest, `System.Xml` for WebDAV bodies. No new NuGet or npm package.

**Spec:** `docs/superpowers/specs/2026-11-07-webdav-design.md` (approved, not to be edited). Brief: `docs/superpowers/overnighter/2026-11-07-webdav-brief.md` (its "Open points for the run" 1–11 are folded in below and referred to as *OP n*).

## Global Constraints

- No new NuGet or npm package; WebDAV by hand, XML through `System.Xml` with `XmlReaderSettings { DtdProcessing = DtdProcessing.Prohibit, XmlResolver = null }`, bodies at most 64 KB (spec §5).
- British English everywhere; new C# and TypeScript files start with `// SPDX-License-Identifier: AGPL-3.0-or-later`.
- No organisation, customer or employer names; examples use Alice, Bob, Carol, `Work`, `Personal`, `kumbu.example.org`.
- A share's password (token) never reaches a log, a URL, or any response other than the creating one (spec §3.3, §5).
- Every write that adds data passes the quota; removing, moving, emptying the trash always work (spec §3.10).
- No agent can delete permanently: emptying the trash is the owner's session with the password, nothing else (spec §3.11).
- Client junk never reaches MongoDB (spec §3.8); an unsupported file fails with 415 and `AttachmentFormat.UnsupportedMessage`.
- A server updated to this version behaves as before until `KUMBU_QUOTA_DEFAULT` is set or a share is created.
- Not touched: encryption scheme, existing slot kinds' derivations, sessions and their password window, OAuth, pairing, `CallerMiddleware`'s rules for `/mcp` and `/api`, publish rules.
- Time-dependent behaviour goes through the injected `TimeProvider`; tests use `FakeTimeProvider` (as `tests/Kumbu.Server.Tests/Api/ChangesetIdleTests.cs:17`), never sleep.
- `web/src/api/schema.d.ts` is edited by hand, as generated output would have it.
- Commit after every task, imperative free-form message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; push only to `feature/webdav`; never force-push; never merge.
- Test filter: `dotnet test --project tests/Kumbu.Server.Tests -- --filter-class "*ClassName"`. Tests need `KUMBU_TEST_MONGO` pointing at a fresh replica-set container `kumbu-test-mongo` (`--ulimit nofile=20000:20000`), recreated with `docker rm -fv kumbu-test-mongo` before every full run.

## Review Focus

1. **Usernames with a dot** (`alice.smith.k7qm`): the share id is the part after the *last* dot; the rest must equal the owner's username. Test in Task 2.
2. **Percent-encoded and non-NFC hrefs** (`Caf%C3%A9.md`, decomposed `é`, `%2F` inside a segment, a trailing slash on a file): each path is decoded once, NFC-normalised, and refused (400/403, never a different file) when it contains `..`, an empty segment or an encoded slash. Test in Task 5.
3. **A `Destination` header with another host, `http` vs `https`, or a path outside `/dav/`**: 502, nothing moved. Test in Task 9.
4. **A chunked `PUT` larger than the limit with no `Content-Length`**: 413 after counting, nothing stored (OP 6). Test in Task 8.
5. **Two shares of one user on one machine** writing the same parked name: each sees only its own (spec §3.8). Test in Task 7.
