### §2.7 F-03: a link to a heading opens the note at that heading

Commit `10655da` "Open a link to a heading at that heading".

## Decisions made without Chris

1. **Where days off are kept.** Options: in plain on the user document beside the zone, as spec §2.4 says; sealed, like the vault names. A week's shape can hint at a religion, which a zone doesn't. I followed the spec (it is approved and settles the storage) and recorded the question for Chris in `open-items.md`.
2. **A heading link to the note itself, `[[#Heading]]`.** Options: make it jump too; leave it as text, as today. The spec names `[[Note#Heading]]` only, and an existing test asserts the self link's behaviour, so it stays text (rules 1 and 5). It is a few lines for the UI round.
3. **Two headings of the same name.** The spec says "the first wins, as `cat note#section` resolves it"; `cat` in fact refuses such an address as ambiguous. The web takes the first, as the spec's words say: a link should open somewhere, and the notice would be wrong. A heading answers to its text as written and as shown, so a link an agent writes in `cat`'s form works; slugs such as `#next-steps` are not read, as neither `cat` nor Obsidian reads them.
4. **F-02's place.** Options: change `Menu.tsx`, the tree's scroll in `TreeDrawer.tsx`, or both. Only `Menu.tsx` changed: it can tell the person's scroll (wheel, finger, a held press or key) from any other, for every menu, and the tree keeps its scroll to the open note. A key only marks a press and doesn't close the menu itself, so Space on the button doesn't close and reopen it.
5. **Ctrl+S with a dialog open.** Options: prevent the browser's Save page; leave the key alone. The spec says "does nothing new", so the key is left to the browser.
6. **When the last note opens.** Only at a page load's start, never on a later `/` in the same page; a vault chosen before the shell shows (Share's "Open X") wins over it; a note is kept only once it has loaded; if the kept vault's tree can't be read, that vault starts without forgetting the note. Options were "every time the vault list shows" (it pulled the person away from where they went) or once per page load; I chose the latter, which is what "on start" means. Forgetting also on account deletion and as the vault is marked discreet, before the list says so: cheap, and it narrows what a device keeps.
7. **`PUT /account/calendar` with `{}`.** It used to clear the zone; now it leaves both as they are, as "a field left out stays" requires. Neither the web app nor the suite sends `{}`.
8. **A note in a sub-folder of `Board/`.** The spec excludes `Board.md` and `Board/Archive/`; the board shows no note of any sub-folder, so "In Running" would not be true there. Such a note is no card: no board line and no fold.
9. **Which flags fold the box.** Only the eight known flags, ignoring case, as the header reads them; `flag/maybe` keeps the box.
10. **No fold control while the box shows its tint.** It shows open, as the spec says; the control comes back once the tint goes.
11. **The ← and → keys.** Only in the desktop layout (where the tree docks), never in a text field, a menu, under a dialog or with a modifier, and not after another handler took the key.
12. **The shading in dark schemes.** Mixed towards each scheme's `--muted`, so it is the same kind of step in all 17 schemes; in a dark scheme it lightens, since nothing is darker than a near-black page. Recorded for Chris (UX check).
13. **The end-to-end start test (§2.5 #1).** It asserts the note's row is current and visible in an open folder, not that it is scrolled into view: opening the same note by its address today leaves it at the same place. Whether "the tree at it" should mean scrolled to is a follow-up.
14. **F-02's regression test** scrolls the tree's list by setting its `scrollTop`, not with `scrollIntoView`, which also scrolled the page and moved the wheel's point onto the menu. Both are scrolls no person makes.
15. **"+ Today" and "+ This week"** take the 48 px from the shared button class with one line, as other calendar controls do; the arrow and the label below the week are joined so the arrow never wraps alone.

## Deviations and open points

- **A fast second → in the week view** before the next week's data has arrived lands on the same week again: the old "next" is reused. A person holding → would stall the same way. Minor, for the UI round; the end-to-end test waits for each week's title.
- **The start (§2.5) doesn't scroll the tree to the note** when many folders sit above it (decision 13).
- **The vault's root and the vault list share the heading "Your vaults"**, so the start test tells them apart by the tree and the forgotten key instead.
- **A closing `touchmove` on iOS Safari:** the menu closes on a finger's first move; on a real iPhone a tap with a tiny move might still click through. Chromium's emulation can't show it; worth a look on a phone.
- **A board card with a date** shows its column twice, in the calendar line and in the board line. The spec asks for the board line on every card; for the UI round.
