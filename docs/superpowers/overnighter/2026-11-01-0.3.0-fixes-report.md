## 6. Surprises

- **Task 1.9 introduced a regression that Task 2.5's sweep found.** The connection view now sent rights already capped by her role, so "Change rights" saved the capped value and a member's stored write silently became read. Task 1.9b fixed it. The review of Task 1.9 had passed it, because the spec asked for the capped display.
- **The contention test of Task 1.8 could not fail at first.** Its release phase saw only the rate limiter, so the timing assertions could never fail. The fix round gave the test its own host with a rename limit of one million. Without the check, an unrelated reader's read then waited 21 s, or past the 60 s bound.
- **Task 3.5's menus and VoiceOver.** The first version portalled menus to `body`, which leaves an `aria-modal` drawer, so VoiceOver could not reach the items. The fix portals into the closest modal dialog. That in turn needed `flushSync` for Tab past the last item, found because the dialog Tab test failed.
- **Single failures that did not reproduce:** one in the Task 2.3 server run (117 tests) and one in a Task 3.5 full web run (1 of 1319). Neither was identified.
- **Task 3.2:** the hidden username field became the first focusable control in every dialog. The full suite caught it (a Settings test), not the new tests.
- **Task 3.3:** the sync socket never reaches the access-list query, so there was no hint to wait for.
- **Task 3.7:** in jsdom the focus defect reproduced only with a delayed tree. The real trigger may be another route into the same fallback (`Share.tsx` sets the overlay "tree").
- **Task 1.3:** the first version of the busy-gate test ran on the real clock and raced the held fetches' own 5 s timeouts. It now runs on a fake clock.
- **Task 1.1:** an existing test configured `http://pdf:8090` yet connected to `pdf:<random port>`. The new host and port check exposed it.
- **Task 1.5:** `Users.tsx` needed no change, because the generic password-window handling already repeats a guarded 401. The web tests pinned existing behaviour.
- **Task 1.6:** two mutants survive, and both are equivalent or untestable (section 4.1).
- **Task 1.2:** after the writer was dropped, the web's move-hint parser matched only because the REST text happens to append " (if it was removed…". The final review caught it (M6), and the fix wave changed the pattern.
- **The citations.** Several in the security architecture had been renumbered mechanically, which carried over errors that existed at the base. The final review found about a dozen wrong ones, so the wave re-read every citation in six files.
- **The final review's own note:** it said the phase 3 gate was missing from the ledger. The gate had been recorded after the review began.
- **Commit messages:** the review notes that two messages (`4f7e24e`, `6f3122d`) each state the old weakness in one clause. Neither is a recipe, but the squash message and the PR text should keep to what is now true.
