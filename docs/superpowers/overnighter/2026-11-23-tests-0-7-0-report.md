# Report: the specific test run of 0.7.0, with search by meaning on

The run wrote end-to-end tests for every 0.7.0 feature but offline mode (whose seven tests existed), filled the offline mode's gaps, and ran the 0.7.0 set in the browser and over MCP, with search by meaning **on and the real model** (arctic-m) for the features that stand on it, and through TensorX for an external provider and BYOK. It found **17 findings** (7 over MCP, M-01 to M-07; 10 in the browser, F-01 to F-10), none High; two of them (F-06, F-10) are intermittent and wait as `test.fixme`. The product is unchanged: nothing under `src/`, `web/src/` or `web/sw/` was touched, and no `data-testid` was added.

### How the model and TensorX were reached

- **The VM's proxy** listens on `127.0.0.1:39379` (`HTTPS_PROXY`). A bridge-networked container can't reach the host's loopback.
- **The build stages** reach npm and NuGet as in 0.6.0: Docker's own traffic goes out through the VM's transparent egress, which re-signs TLS, so the build stages need only the CA (`compose.proxy-ca.yaml`).
- **huggingface.co** answered 200 from the VM through the proxy, and from a throwaway container (`curlimages/curl`) directly with the CA.
- **TensorX** (`POST https://api.tensorx.ai/v1/embeddings`, `Authorization: Bearer <placeholder>`):
  - from the VM through the proxy: **200** (the proxy *replaces* the header with the real key);
  - from a container directly (the transparent egress): **401** with the placeholder and without a header (no key is put in there);
  - from a container on the stack's network through the relay below: **200**.
- **So the search overlay sends the server through the VM's proxy** (`compose.search-proxy.yaml`): a relay service on the host's network (`proxy-relay.mjs`, a byte-for-byte TCP pass, listening only on the Docker bridge's gateway address `172.17.0.1:39380`, which `host-gateway` names inside the containers), `HTTPS_PROXY=http://host.docker.internal:39380` and `NO_PROXY=mongo,pdf,localhost,127.0.0.1` for the server, the CA bundle (`/root/.ccr/ca-bundle.crt`, 120 certificates, 0644) mounted with `SSL_CERT_FILE`. The model (630 MB) and the tokenizer came through it into the external volume `kumbu-e2e-models`.
- **The emergency forwarder wasn't needed** (brief, open point 5): the proxy replaces the header, so both the `tensorx` provider and BYOK reach TensorX authorised. **A key typed into Settings passes BYOK's check only because the proxy replaces it**: the placeholder (`e2e-placeholder-byok-key`) is never a valid key. The run never saw the real key.

## Decisions made without Chris

1. **The search overlay** (open point 1): `E2E_SEARCH=1` (not a `COMPOSE_FILE`), as the spec names it. The proxy through a relay on the host's network at the bridge's gateway, because the proxy listens on the host's loopback; the CA mounted with `SSL_CERT_FILE` (a full bundle, readable by `app`) rather than a CA-carrying copy of the final base, as it needs no build step. *Options:* `network_mode: host` for the server (would bind its port beyond 127.0.0.1 unless reconfigured, and lose the stack's network), the relay as a host process started by `up.sh` (a process outside Compose to track), the relay as a service (chosen: Compose starts and removes it).
2. **The model's download kept out of the tests' bounds:** `up.sh` waits for "Embedding model loaded". *Why:* reproducible from a fresh volume.
3. **The proxy only for the search stack:** the off phase's stack is the one of 0.6.0, unchanged.
4. **The fixtures for meaning** (open point 2): six short notes on three topics; arctic-m's ranking looked at once and recorded above. No clear case came out wrong, so no rerun on a fresh stack was needed for that.
5. **The floor of 0.5** (open point 3): no unrelated pair of the fixtures passes it (highest 0.32); not a finding.
6. **Waiting for embeddings** (open point 4): the command's own error line and counts line, `/api/similar`'s `state`/`pending`; 180 s for the first note, 60 s after.
7. **TensorX** (open point 5): the proxy replaces the header, so no forwarder; BYOK included.
8. **Users for deactivation and BYOK** (open point 6): made through Alice's admin invitation, deleted afterwards (not "reactivated and left"), so the stack keeps no state of them.
9. **`@since-0-7-0`** (open point 7): the marker on every new `@graph` test without `@search`, and `e2e:0.6.0` inverts it; the selection checked against the base. *Options:* a new tag name for the graph (the spec names `@graph`), or accepting a changed 0.6.0 selection.
10. **The discreet places** (open point 8): the offline copy's vault list is gaps #4 (it needs the offline helpers), the other four in `discreet-0-7-0.spec.ts`; Similar notes' and the graph's checks compare a hidden vault's answers with a made-up vault's, since a Work note can never suggest a Home note.
11. **F-06 intermittent:** `test.fixme` with the rate, as 0.6.0 did with its F-10 (this run's F-10 is another finding). *Options:* a plain assertion or `test.fail` (the two runs would differ).
12. **Publishing switched off** (spec §2 `@overview`): left out, Vitest named. *Options:* a third phase on a stack with `Kumbu__Publish__Enabled=false` (another 5 minutes per run, for one line).
13. **F-10 split off as `fixme`** after a final run showed it once: the rest of devices #4 stays a plain test.
14. **The search-off findings confirmed on the off stack** before marking them (M-06, M-07, F-08, F-09), as a reviewer had predicted M-06 from the code and the run then showed M-07 too.
15. **`unindexed` asserted by shape only** (similar-api #11): the first answer after a write may be `unindexed` or already `ready`; only an `unindexed` answer's shape is asserted, so the run stays deterministic.
16. **The selection check** listed as `run.sh` runs its phases, after a `--list` without `--project` had listed every test.

## How to run the suite

- **The 0.7.0 run:** `E2E_PROXY_CA=/root/.ccr/ca-bundle.crt pnpm -C web e2e:0.7.0` (behind a TLS-re-signing proxy; elsewhere without the variable). Two fresh stacks, search off then on; the first search stack downloads the model (630 MB) into `kumbu-e2e-models`, later ones reuse it. About 18 minutes.
- **TensorX:** `E2E_PROXY_CA=… pnpm -C web e2e:0.7.0:tensorx`. Needs the environment's proxy secret for `api.tensorx.ai`; elsewhere a real key in `web/e2e/stack/tensorx-placeholder-key` would do (never commit one).
- **While writing tests with search on:** `E2E_SEARCH=1 E2E_PROXY_CA=… web/e2e/stack/up.sh`, `pnpm -C web exec playwright test --project=setup`, then `--no-deps --project=<p> --grep "@tag"`; wait for embeddings with `support/search.ts`; `down.sh` with the same variables.
- **Without search:** as in 0.6.0 (`up.sh` without `E2E_SEARCH`).
