- **Commit messages** are imperative and free-form, with no Conventional Commits prefix, may name the finding (F-08 …) in the body, and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage files by name, never `git add -A`, `git add .` or `commit -a`.

## Deciding without Chris

When the spec leaves something open, or something unforeseen comes up, choose the option that satisfies these, in this order:

1. **Breaks nothing.** Existing behaviour, data and interfaces keep working, apart from what the spec changes. Prefer the reversible change.
2. **True to the spirit of the application.** Campy: plain notes and frontmatter, no new stores. Human-centric: the screen speaks of the person's wish. Honest: a button does what it says, and nothing is hidden quietly.
3. **Opens no new security hole.**
4. **True to the spec.**

If a question can only be answered by changing the spec's scope, don't guess: leave that part out and record it in `docs/superpowers/open-items.md`. If a soft constraint (a file left to the sibling run, a "smallest change") makes a fix many times bigger, leave the fix out and record why rather than forcing it.
