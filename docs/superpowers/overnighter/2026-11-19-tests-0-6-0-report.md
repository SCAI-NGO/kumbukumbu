# Report: the MCP suite and the specific UI run for 0.6.0

The run added an MCP project to the Playwright suite (`web/e2e/mcp/`, no browser, no model in the loop) and browser tests for 0.6.0's new UI, each tagged by feature, and ran `pnpm -C web e2e:0.6.0` from nothing until two runs in a row gave the same result. It found **13 findings**: 3 over MCP (M-01 to M-03) and 10 in the browser (F-05 to F-14), among them one High (F-10, a discreet vault's note left in the clear), and a few open points for Chris. The product is unchanged: nothing under `src/` or `web/src/` was touched, and no `data-testid` was added.

Pull request: https://github.com/SCAI-NGO/kumbukumbu/pull/261 (branch `feature/tests-0-6-0`).

## Environment

- **Machine:** 4 CPUs, 15 GB RAM, Linux 6.18, the clock in UTC. No container restart during the run.
- **Node 26.13.1** was already in `/opt/node26` (the cloud environment's setup script). **pnpm** was 10.28.0; I installed 10.32.1 with `npm install -g pnpm@10.32.1`.
- **Docker 29.10.0, Compose 5.7.1, buildx 0.39.0** were installed; `dockerd` wasn't running, so I started it.
- **Playwright 1.63.0** with the pre-installed Chromium 1243 in `/opt/pw-browsers`: `playwright install` was skipped (decision 6).
- **The image build** needs `E2E_PROXY_CA=/root/.ccr/ca-bundle.crt` behind the session's proxy, as in 0.5.0 (`web/e2e/stack/compose.proxy-ca.yaml`).
- **Superpowers:** loaded. The work ran subagent-driven: one fresh implementer per task, then one fresh reviewer per task, fix rounds that resumed the implementer and re-reviews by the same reviewer until the verdict was clean. Two to four implementers worked at a time on one shared stack, each in its own files and running only its own tag. I committed and pushed; subagents never did. Where a last round held one or two small fixes, I made them myself and said so in the commit (`files`, `deeplinks`, `upload`), or checked the diff myself instead of a third re-review (`publish` round 3, `palette` F-13, `console` round 3).

## The plan and its review

The plan is `docs/superpowers/plans/2026-11-19-tests-0-6-0.md`. A fresh subagent reviewed it with the spec and the brief, not my reasoning, and found 17 points, all folded in before Task 1 (the plan's last section lists them). The ones that changed the run most:

- **Sessions idle out after 30 minutes** (`Sessions.cs:31-32`) and the setup can't run twice on one stack. While writing, a keep-alive outside the repository kept the dev stack's sessions alive (decision 3); the final runs start from nothing and don't use it.
- **The password budget:** an invitation checks the password window and the password in its body; a vault's deletion checks it again. `share.ts` books every check through `reservePassword`, and the setup's two checks are booked too.
- **Finding ids** continue after 0.5.0's F-01 to F-04.
- **Vault-wide lists in MCP tests** are scoped to the test's folder or a random tag (`calendar`, `graph --orphans/--hubs/--unresolved`, `publish ls`), because the `mcp` project has no serial phase.
- **Secrets in failed assertions:** `redact()` (`web/e2e/mcp/fixtures.ts`) before any assertion on an answer holding an upload URL, a reader link or a key.
- **Bob accepts through the API** so the `mcp` project needs no browser (decision 2).

### F-10 (High, bug, intermittent): a hide from elsewhere can leave a discreet vault's note in the clear

- **Test:** `web/e2e/discreet/discreet-0-6-0.spec.ts`, both `test.fixme` tests:
  - "discreet-0-6-0 palette: hidden from elsewhere (here with the palette open), the address leaves the note (F-10)";
  - "discreet-0-6-0 windows: hidden from elsewhere while a window is open over a Home note … (F-10, F-11)".
- **Steps:**
  1. Alice, in a session of her own, shows Home with the PIN and opens `/Home/Zahnarzt.md` (the address shows `/discreet`).
  2. She opens the palette (or a window) over it.
  3. Home is hidden from elsewhere: `POST /api/account/discreet/hide` from the session's request context, which the tab hears through its sync socket.
- **Expected:** the address becomes the last ordinary note's (palette spec, anti-goal 1; windows spec, anti-goal at line 28: nothing of a hidden vault stays). The shell behind a window shows nothing of Home.
- **Actual, now and then:**
  - the address stays `http://localhost:8080/notes/Home/Zahnarzt.md`, in the address bar and in the tab's history, with "There is no such note";
  - once, Zahnarzt was back in the palette's Recent;
  - under a window, the shell behind showed "Switch vault: Home" and the tree headed Home.
- **How often:** with the palette open, about 2 in 5 runs on the phone and 1 in 10 on the desktop. It also leaked once with the palette closed, so the finding is not tied to the palette. A hide with ✕ in the same tab never failed.
- **Evidence:** with every `history.pushState`/`replaceState` recorded by an init script, exactly one write follows the hide: `replaceState /notes/Home/Zahnarzt.md` from React Router's `history.replace`, made after the discreet names were reset.
- **Likely place:**
  - `web/src/discreet/hideAgain.ts:179-201`: the reset comes before the navigation;
  - `web/src/discreet/neutralWindow.ts`, `write()` (around line 95): it neutralises only a replace without a URL, not one naming a vault that was discreet a moment ago;
  - whatever replaces the location when the palette or a window closes (`web/src/palette/Palette.tsx`, the URL effects around `web/src/shell/MobileShell.tsx:336`).
- **Why fixme:** a plain assertion or `test.fail` would make the run differ between runs (decision 9). The fix run lifts `fixme` once it is fixed.

## How to run the suite

- **The 0.6.0 specific run:**

  ```bash
  pnpm -C web e2e:0.6.0
  ```

  Behind a TLS-re-signing proxy, prefix `E2E_PROXY_CA=<CA file>`. The script brings the stack up from this checkout, runs `--grep "@smoke|@memory|@graph|@svg|@deeplinks|@upload|@publish|@blame|@files|@readers|@shell|@palette|@windows|@filters|@console|@workspace|@calendar"` in two phases, takes the stack down with its volumes, and exits with Playwright's worse exit code. About 10 minutes.
- **The MCP suite alone:** `pnpm -C web e2e --project=setup --project=mcp`.
- **While writing tests:**
  1. `web/e2e/stack/up.sh` (with `E2E_PROXY_CA` where needed), then `pnpm -C web exec playwright test --project=setup` once.
  2. `--no-deps --project=mcp --grep @tag`; `--no-deps --project=desktop --project=phone --grep @tag`; `--no-deps --workers=1 --project=serial --project=serial-phone --grep @tag`.
  3. Pass `--output <folder>` when several people run at once: `e2e/.results` is shared.
  4. The saved sessions idle out after 30 minutes; the setup can't run twice on one stack, so `down.sh`, `up.sh` and the setup again.
- **New MCP tests** use `web/e2e/mcp/fixtures.ts` (no browser). They scope every vault-wide answer to their own folder or tag, and pass an answer holding a link through `redact()` before asserting on it.
