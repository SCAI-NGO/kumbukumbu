# Report: the fixes of the 0.6.0 UI tests

The run fixed the findings of the 0.6.0 UI tests outside the discreet and skills code (spec `docs/superpowers/specs/2026-11-19-0-6-0-fixes-design.md`): **M-03, F-08, F-12, F-13** (Medium) and **F-05, F-06, F-07, F-09, F-14, M-02** and `rm`'s wording (Low). Every finding's test went red before its fix and green after it, every fix's mutations turned a test red, and a fresh reviewer checked each fix. Nothing was left out. Pull request: https://github.com/SCAI-NGO/kumbukumbu/pull/263 (branch `feature/fixes-0-6-0`).

## The fixes

### F-12 and F-13: the keyboard menu (commit `83072d4`)

- **Root cause, measured in Chromium** (palette #9 on the baseline, with a probe): the menu was placed above the dock's ⋯ (button top 732, window 800) for the list as it then was, 586 px tall: `top: 138px; max-height: 716px`. The held favourites and publications arrived, the list grew to 716 px (scroll height 728) downwards from 138 and was never placed again: bottom 854. F-12: `PointMenu.tsx:44` focused the first item in the measuring effect, while the list still had `visibility: hidden`; Chromium focuses no hidden element, jsdom does.
- **Fix** (`web/src/components/PointMenu.tsx`): `place()` sets the placement only when it changes; it runs when the point or the items change, and from a `ResizeObserver` on the list when its size changes; the first item takes the focus once, in a layout effect on whether the list is placed, so placing again never moves the focus; the scroll and resize listeners in their own effect.
- **Red** (Vitest, 3 of 10 failed): `is_placed_again_when_its_items_change_and_keeps_the_focus_where_it_is` (`expected '704px' to be '264px'`), `is_placed_again_when_its_size_changes` (the same), `focuses_the_first_item_only_once_it_is_visible` (`[['Rename', true]]`: focused while hidden). Green: 10 of 10, `useNoteMenuKey` 9 of 9.
- **Mutations**, each red: the focus back in the measuring effect; the items out of the placement's dependencies; the observer calling nothing; the focus effect on every placement (the focus jumps back to the first item).
- **Browser:** #8 asserts the focused item by its text before and after ↓, Esc with the caret back, Shift+Tab on the first item closing it; #9 the box within the window, top and bottom; #10 the focus in Read mode. The assertions by item and the top edge came from the review (commit `8b7af74`, mine).
