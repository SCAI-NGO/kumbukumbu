- **Docker** test containers are available and allowed, set up by the environment's setup script (a `dockerd` with `socat`). The server tests start MongoDB through Testcontainers (see `tests/Kumbu.Server.Tests/TestImages.cs`).
  - If `docker info` says "Cannot connect", please check whether the setup script's daemon is still running, and start it again if you can.
  - If Docker can't work at all, use an external replica-set MongoDB: install `mongod`, start it as a single-node replica set, and set `KUMBU_TEST_MONGO` (see `ExternalMongo` in `TestImages.cs`).
  - An earlier run met a hard file limit below what Testcontainers' `mongo` asks for. What worked was a container of your own with `--ulimit nofile=20000:20000`, named `kumbu-test-mongo`, as a replica set, and `KUMBU_TEST_MONGO` pointing at it.
  - Give every full run a fresh container, with `docker rm -fv kumbu-test-mongo` first: mongod runs out of file handles over many runs, and without `-v` anonymous volumes fill the disk.
  - If Ryuk gets in the way, `TESTCONTAINERS_RYUK_DISABLED=true` is fine.
- The 4 skipped tests need the real embedding model and a TensorX key. Neither is available here, and skipping them is expected. Running as root can skip 2 more.
- **No dry run.** The planning machine has no .NET SDK, Node or Docker, so nothing in the plan has been run, and its anchors come from reading the code. Trust the code over the plan's line numbers. If a task's premise turns out wrong, choose the reading closest to the spec and write it down.

## How to work

- Task by task as in the plan: a fresh subagent does red test, green, commit, then every mutation individually (break, watch it fail, restore with `git checkout -- <file>`). Then a spec-compliance review and a code-quality review, each by a fresh subagent.
- Subagents never merge, push or switch branches. You commit and push.
- The test filter is Microsoft.Testing.Platform's: `dotnet test --project tests/Kumbu.Server.Tests -- --filter-class "*ClassName"`, repeatable. `FullyQualifiedName~` doesn't work here, and a glob in mid-name selects nothing.
- Commit and push after every task. Commit messages imperative and free-form ("Let a second tab follow a rename"), no Conventional Commits prefix, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Full verification at the end of each phase, as CI does: `dotnet restore --locked-mode`; `dotnet build --configuration Release --no-restore`; `dotnet test --configuration Release --no-build`; `pnpm -C web install --frozen-lockfile && pnpm -C web test --run && pnpm -C web build`; `pnpm -C pdf install --frozen-lockfile && pnpm -C pdf test && pnpm -C pdf build`.
- **The web's CI gate is `pnpm -C web build`:** it runs the type check, which `pnpm test` does not.
- Known failures before you start: **none**. Expected: `dotnet test` total 3666, 3662 succeeded, 4 skipped, 0 failed; web 88 test files, 1567 tests; sidecar 8 test files, 146 tests (CI run 41706062496).
- Only `dotnet build`, `dotnet test`, `pnpm test` and `pnpm build` output count as evidence.
- **Style:** British English in code, comments, docs, commits (colour, behaviour, initialise, licence as the noun). Match the surrounding code's naming, idiom and comment density; comments only where the reasoning isn't obvious. New C# and TypeScript files start with `// SPDX-License-Identifier: AGPL-3.0-or-later`.
- **`web/src/api/schema.d.ts` is edited by hand here**, as generated output would have it.
- **The repository names no organisation, customer or employer**: code, docs, tests, examples, test data. Use Alice, Bob, Carol, `Gartenarbeit`, `Work`.

## A few things that matter to us

- Please do not merge, tag or deploy, and don't change the version: rollout is something Chris does himself. One draft pull request is the result.
- No secrets in logs, assertions or the report.
- Specs outside this topic stay as they are; if one looks wrong, mention it in the report.
- **`history` hides nothing, by Chris's decision.** It has something of an audit log about it: both lines stay, and the upper one says `(restored)`. A stored flag decides this, since A, B, A in one changeset looks like a restore otherwise; a false mark is worse than none. The stored push of a restore stays too, since it protects restored text, and the history rule doesn't change.
- **Nothing revokes a device key without the person's click.**
- **Security boundary:**
  - **Touched:** `src/Kumbu.Server/Vaults/` (Task 6, `_loading`). It gets its own security review by a fresh subagent. Its invariant: during a two-key period, no object made with the old vault key is served or writes.
  - Touched lightly: `src/Kumbu.Server/Sharing/VaultEvents.cs` (Task 5). One member must not learn who else lost keys.
  - **Not touched:** authentication, sessions, API-key rights, crypto primitives, slots, pins, `CallerMiddleware`.
- At the end: a row with the pull request's link in `docs/superpowers/open-items.md`, and in the report a hand-test section with numbered steps, where to look and what passes: Chris tests from that list. Don't change anything else outside the plan's files.
