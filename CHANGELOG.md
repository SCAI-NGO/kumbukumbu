# Changelog

What changed for the people who use and run Kumbu², per release. Older releases are described in their pull requests.

## 0.6.0 (2026-11-22)

Kumbu² becomes a memory you share with your AI: agents keep their project memory as notes you own, upload files and read spreadsheets and web pages, while you publish a note with the notes it links to, see who wrote what, and work with a palette, a split view and a first look at the graph.

### New

- **Kumbu² as a project memory for AI agents.** A new system skill, **project-memory**, tells an agent how to keep its memory as notes you own: a folder with a `MEMORY.md` whose front matter names the project it belongs to (`project:`), or none, for what holds everywhere. The agent reads it at the start, writes down what is worth keeping, and every write is a version in history, by a key you can see. Nothing assumes you work in projects; it is a convention, not new code. A skill of your own in your Skills vault with the same name takes its place.
- **Start-up skills.** A skill marked `metadata: { kumbu-when: session-start }` is named first when an agent connects, with "Hint only" keys too, so the agent follows it before its first answer. The mark counts for system skills and for skills in your own vaults that you changed last; one from a shared vault, or changed by someone else, stays an ordinary skill.
- **Say why with a write.** `write`, `edit` and `replace` take a short `message` (one line, up to 200 characters); `history` shows it, and so does the history in the web app.
- **The link graph, for agents and apps.** `sh graph` shows what a note links to and what links to it, up to three steps deep; `graph --path A B` finds how two notes are connected (or says they aren't, within six steps); `--orphans`, `--hubs` and `--unresolved` find lonely notes, the most linked ones, and links to notes that don't exist yet. `/api/graph` serves the same to the web app.
- **Preview: a graph of the note** (#274). On a wide screen a column beside the note draws it with the notes it links to and that link to it; elsewhere the graph opens as a dialog, where you pinch, pan and double-tap to fit. Hover a node to preview its note, click to open it. It is a preview: it is there to try and costs nothing if you leave it closed, and we want to hear what you would use it for and what is missing before it counts as done.
- **Notes remember when they came into being.** From this version on; for older notes Kumbu² gives the oldest date it still knows, marked "at the latest".
- **SVG pictures.** A vault keeps `.svg` files beside its notes and shows them as images, embedded with `![[diagram.svg]]` as in Obsidian, in the web app, on published pages and in exports. Agents draw them: `write` takes an SVG whole, `cat` prints its source, and `img` shows how it looks, so an agent can see what it drew and correct it. An SVG is shown as an image only, never as part of the page, so nothing in it runs and nothing it refers to is loaded; a published SVG keeps no paths from the computer it was made on.
- **Links that agents can show you.** After writing or reading a note, an agent gets a link that opens it in the web app with one tap (after sign-in); it works for every member of a shared vault, whatever each of you calls the vault, and a file opens in the viewer. A link to a note that was moved or removed, or that is in a vault you can't see, leads to one "Not here" page with the search. Behind a proxy, set `KUMBU_PUBLIC_URL` so the links name the right address.
- **Agents can upload files.** An agent with a shell asks Kumbu² for a one-time upload link (the new `upload` tool) and sends an image or PDF there with `curl`, so the bytes never pass through the model; the file is stored as that agent's write, and the answer says what to put into the note. A link works once, for one file, for ten minutes, over HTTPS only. The README section "Agents uploading files" says how to let your agent's sandbox reach your server; behind a proxy, set `KUMBU_PUBLIC_URL` and trust the proxy so the links work.
- **Publish a note with the notes it links to** (#235). In **Publish…** you choose how far to follow links, from "this note only" up to five steps, and see every note that goes out and everything that stays behind, with the reason, before anything is published; you can untick single notes, and from 50 notes on the dialog warns in red. A note marked unpublishable is never taken and the walk doesn't go through it; mark, move or remove a note later and it leaves the copy at once, along with the notes reached only through it, while the rest stays published. Readers get one link with a Contents list, links between the notes that land on the right heading, and Copy as Markdown and Link for your AI for the whole set; they never learn that a note was left out. Agents do the same with `publish add <note> --depth N`, `--without` and `--dry-run`. At most 500 notes and 64 MB per publication; single-note publications work as before.
- **Your own TensorX key for search by meaning** (#234). Where the admin sets `KUMBU_EMBEDDINGS_BYOK=true` and the server embeds with its own model, you can save a TensorX key in Settings and use TensorX's better embeddings for the vaults you choose, on your own account; new vaults start on it once a key is saved, and the app asks once whether to move your existing vaults. Your notes' text and searches then go to TensorX under your own contract. The key is sealed, checked before it is saved, never shown again apart from its last four characters, and can be replaced or removed at any time: removing it moves your vaults back to the server's model at once. Discreet vaults never use it. On a server whose admin pays for an external provider, the option doesn't appear.
- **Several changes in one `edit`:** `edits` takes a list of `{old_text, new_text}` pairs, applied in order to one version, all or none.
- **`ls -l` and `ls -a`** (#233). `-l` shows each entry's size and last change, a folder the newest change below it, so an agent sees what is new and what is large in one call; `-a` is short for `--archive`. Start a new agent session after the upgrade so it reads the new usage.
- **Filters for Users, Invitations and Access** (#236). Each of these lists has a search by name (for invitations, by their note), ignoring capitals, and a choice of status with how many entries each holds, such as "Open 3 · Used 30 · Expired 8", the counts following what you typed. A list always opens showing everything, and the filter lasts only while the view is open; "Showing 3 of 42 · Show all" says whenever it hides something, also to screen readers.
- **Shortcuts and peek in the console** (#233). `l`, `la` and `lsa` stand for `ls -l`, `ls -a` and `ls -la`; `p <note>` (also `#Section` or `#^block`) shows a note rendered as in the note view, with working links, right in the console. Agents don't get these; they are the console's own.
- **Autocomplete in the console** (#239). Tab completes vaults, folders, notes and commands as in zsh: a unique match fully, several to their common start, and the next Tab lists them; when nothing matches, the line flashes once. On the phone a row of suggestions above the input does the same with a tap, and after `cat ` it offers the folder you're in. Names with spaces go in escaped, so you can keep typing.
- **A command palette, with favourites** (#237). Ctrl+P (⌘P on a Mac), or the star in the top bar, opens a list of commands (Settings, Admin, Recent, What's on, the console, the colour schemes), your vaults with their board, calendar and gallery, and your notes by name; type a few words in any order to narrow it, and the last row hands what you typed to the search. Star anything with the star or Ctrl+D and it stays on top, on every device you sign in on; with nothing typed, the palette shows your favourites and the notes you opened last. Favourites in a discreet vault disappear while it is hidden and come back when it is shown; what names a vault is stored sealed. A note's menu has "Add to favourites" too.
- **Duplicate a note** (#238). **Duplicate** in a note's menu puts "Copy of …" beside it, with everything but its date: the copy doesn't stand twice in the calendar, and a card stays in its column as a second card. Unsaved text in Write mode goes into the copy; the original stays open, and a notice takes you to the copy with **Open**.
- **A note's actions from the keyboard** (#238). Shift+F10 or the menu key opens the note's menu, in Write mode right at the cursor; and with a note open, the palette lists its actions as "Note: …", so Ctrl+P and "no pub" publish it.
- **A free range in the calendar** (#243). `calendar /Work --from 2026-11-28 --to 2026-12-02` shows any span of up to 366 days, as its weeks and only the days with entries, like `--month`; `--tag` works with it. In `sh` and the console.
- **`rg --regions` points at the matched words** (#245): beside the `crop=` box of the line, a `match=` box around the words themselves, so an agent can show exactly where they stand on the page. It is an estimate where the PDF gives one box for a whole piece of text.
- **Who wrote what** (#253). Kumbu² now notes, with every write, who wrote each line of a note: you in the web app, your Obsidian device, a WebDAV share, an agent by its key or connection. **Who wrote what** in a note's menu (and in the palette) opens a window that shows the note section by section with its writer beside it, "Brita and others" where a section is mixed, and a count such as "12 sections by Brita, 9 by Veyalt"; agents ask `sh blame <note>` (by line, or `#Section`) and `blame <folder>` for every note's lines per writer. The last writer of a line counts, as in git; a renamed note's rewritten links show as the renamer's "(mv)". Whoever may read a note's history sees it, with the same names, and nothing more. For notes from before 0.6.0 Kumbu² reads back as far as the history goes and says so ("earlier than …").
- **Every file can travel with your vault** (#254). Word, Excel, CSV, HTML, scripts, archives, files without an extension: Kumbu² keeps them all beside your notes, up to 15 MB each, through the web app (upload and ZIP import), WebDAV and agents' uploads, with history, trash, moving, checkpoints and export like any attachment. Kumbu² does nothing of its own with them: the web app shows a file as a card with its name, size and **Download**, never a preview, and every way out serves it only as a download, so an uploaded page can never run in your browser. Text files (UTF-8) are for agents too: `cat` prints them and `rg` searches them, so an agent can work on your CSV over MCP. A note still wins a link over a file of the same name, publications leave files out, and a file and a folder can't share a name. The Obsidian plugin keeps syncing notes, PDFs and images only: other files stay where they are, in Obsidian or in Kumbu², and neither side's copy replaces or trashes the other's.
- **Update the Obsidian plugin to 0.3.1 before large files reach a synced vault** (#259, plugin 0.3.1). The sync's list now names each file's size, and plugin 0.3.1 leaves a PDF or image over 15 MB in Kumbu², listed as too large there, instead of downloading it whole; 0.3.0 and older would read it into memory, which a phone may not survive, and would keep trying. Download such files from the web app. Plugin 0.3.1 works with older Kumbu² servers too.
- **Large files, up to 1 GiB each** (#257). Videos, archives, big PDFs and photos now come in whole: the web app uploads them with a progress bar, and WebDAV and agents' uploads take them too. Above 15 MB Kumbu² stores a file in encrypted pieces and streams it in and out, so a large upload doesn't need the server's memory. A large PDF or image is still shown in the browser, but Kumbu² doesn't read it (no text search, no `img`, no thumbnail): it says so. Admins set the bound with `Kumbu:Vaults:MaxFileBytes`; behind a proxy, allow bodies that large and enough time to read them (README, "Behind Traefik"). An import from a ZIP still takes files up to 15 MB; upload larger ones on their own.
- **Agents read spreadsheets, web pages and XML** (#260). `csv` shows a CSV's shape (separator, rows, columns, its header) and the first rows as a table, then any rows, columns or a range such as `B2:D20`, also as tab-separated values for `sort`; Excel's `;` files are recognised. `html` picks parts of a page by CSS selector (their text, a table as a table, an attribute such as `href`), `xml` the nodes of a document by XPath, namespaces included. Nothing in a page runs or loads, an XML file with a DTD is refused, and every call stops after 10 seconds, so a hostile file can't tie up the server. They read text files (UTF-8, up to 15 MB); writing comes later.
- **A side panel beside your note** (#244). On a wide window (from 1280 px) a panel on the right shows **Links** ("Linked from" and unlinked mentions, which leave the note's bottom there) and the **Outline**. While you write, the outline follows your text, unsaved headings included; a click puts the caret on that heading's line, and the heading you are in is marked. Show and hide it with its button at the top bar's right end or Ctrl+Shift+\ (⌘⇧\ on a Mac); your browser remembers whether it is open and which tab. On narrower screens and phones nothing changes.
- **Link completion for headings, blocks and Markdown links** (#251). While you type a link, `[[Note#` offers that note's headings and `[[#` your own note's, unsaved ones included; `[[Note#^` offers the block ids the note already has, with the start of each block's text, and never writes a new id into another note. After `](` the same list writes a Markdown link to the note (`/Folder/Note.md`), and `#` after it offers its headings. A heading goes into the link as it reads, cleaned of characters a link can't hold (`[[Roadmap#The roadmap]]` for `## The **road**map`), so it renders and leads to the heading here and in `cat`. The list ranks notes as the palette does, the note named exactly as you typed first, finds typed paths (`[[projects/pl`), and doesn't open inside code.
- **Note templates** (#255). Put notes in a folder named `Templates` at the top of a vault, and **Insert template** (in Write mode's toolbar, or the palette) puts one into your note at the cursor, as one step you can undo. `{{title}}`, `{{date}}` and `{{time}}` are filled in your calendar's time zone, and `{{date:dddd, D MMMM YYYY}}` and the like take the formats Obsidian's templates know, `Do` ("19th") included. A template's properties are merged into the note's: missing ones are added, lists gain the new items, and what the note already has stays as you wrote it; where that couldn't be done without changing a property, nothing is merged and a hint says so. The template itself stays untouched, so Obsidian reads it as its own. No templates yet? The list offers **New template**.
- **Two notes side by side** (#258). On a wide window (from 1280 px), **Split view** in the note's bar (or the palette) shows your note in Write mode on the left and its live preview on the right, marked with reading glasses; pick another note in the tree and it opens in the pane you chose. Both panes can be edited, one at a time: click into the other pane's text and Write moves there, with the cursor where you clicked, after your note on the other side is saved; a double click or a drag only selects, so you can copy across. The pane you work in is plain to see (an accent line, the other pane dimmed, its note quietly marked in the tree), and the tree, palette, search and Recent open there, while a link opens in the pane you clicked it in. Also **Open beside** in a tree row's menu, Ctrl+Enter on a note in the palette, Ctrl+Alt+click on a link, and Ctrl+Alt+← / → to move between panes. The address keeps both notes (`?beside=`), so reload and back bring the split back; a discreet vault in either pane leaves the address neutral and is closed when you hide the discreet vaults. The live preview never writes: ticking tasks or adding properties waits for the editor. On narrower screens and phones nothing changes.

### Better

- **Settings, Admin, the console, Recent and What's on open as windows over your notes** (#232) instead of replacing them: the note stays where it was, dimmed behind, and closing the window brings you back to it, with Write mode and an unsaved draft intact. Settings has a navigation (Appearance, Vaults, Access, Skills, Calendar, Security, Your data, About) and Admin a window of its own; on the phone a window is a sheet with the navigation behind a tab at the left edge. ✕, Esc and Back close every window, a click beside Recent or What's on closes them too, and Back never reopens a window you closed. While a key or another secret is on show, the navigation waits until you have saved it. Board, Calendar and Gallery stay full pages; old addresses such as `/settings`, `/access/keys` or `/skills` lead to the right place.
- **The console can glow green or amber,** like an old terminal: a Plain · Green · Amber switch in its title bar, kept per device, with a block cursor that blinks only when your system allows motion. Errors now say "Error:" in words in every scheme.
- **`cat` reads several notes in one call,** each under its own header with its own version token, so a following `edit` has what it needs.
- **`rm` and `mv` take several paths;** `mv` moves them into a folder (a target ending in `/`).
- **`rg -g` / `--glob`** narrows a search by path, with ripgrep's rules: `-g '*.md'`, `-g '!**/Archive/**'`, `{a,b}`.
- **`links`, `backlinks` and `mv` are faster on large vaults:** they read from a sealed index of the links instead of reading every note. The first unlock after the upgrade reads every note once to build it, and `df` counts it with your notes.
- **An end time where you add an appointment.** A day's + in the calendar asks for an optional **Until** once you give a time, so "12:00 until 21:00" is one step; **Edit date…** still takes ends on other days.
- **Behind a compressing proxy, the graph and sync answer "unchanged" again.** A proxy that gzips responses marks their version tags as weak (`W/"…"`), so Kumbu² never recognised them and sent everything again; it now compares them as the HTTP standard says.
- **`df` and the memory limit count the link index and the graph** a vault holds open, so the figures match what the server really keeps.
- **MongoDB 9** is what `compose.yaml` runs by default. It starts on the data of MongoDB 8 as it is, and going back to `mongo:8` keeps working until you raise the feature compatibility version; data still at 7.0 goes through `mongo:8.0` first (README, "Upgrading MongoDB"). Taking 0.6.0 with the shipped `compose.yaml` and no `KUMBU_MONGO_IMAGE` therefore moves your database to MongoDB 9 in the same step; to update Kumbu² first and the database later, put `KUMBU_MONGO_IMAGE=mongo:8` into your `.env` before you pull.
- **Long PDFs come out whole when an agent writes them up** (#241). The system skill ingest-attachments now writes a document of more than 30 pages chapter by chapter, reading and writing in turn, and the overview last, so nothing early is lost from the agent's memory by the end. And it marks what it reads into the source: picture descriptions and values read off a chart go into a `> [!described]` box, while the source's own text, tables and numbers stay plain, so months later you can tell what the document said from what the AI made of it.
- **A crop of a scanned page stays sharp, not blown up** (#245). `pdf --crop` inside a picture renders at most at that picture's own resolution instead of enlarging it into mush; and when an image is shown smaller, the note says by how much ("Reduced to 45 % (1 px here is 2.24 px of the original)").
- **A very large board or tag list no longer slows the calendar** (#240). A `Board.md` or a note whose front matter is over 64 KiB is read no further, as aliases already were: the board says its front matter is too large, and such a note's front-matter tags are left out (tags in the text still count). What's on and the calendar read a board once per change instead of on every request.
- **Diagrams are shown more safely** (#242). A Mermaid diagram's image is now a self-contained picture that can never be opened as a page of your Kumbu²; maths in sequence and class diagrams and journey diagrams draw as before.
- **Search by meaning stays quick for everyone on a shared server** (#249). Notes waiting to be embedded are taken one owner at a time, so a person who writes a very long note, or many notes at once, waits for their own backlog while everyone else's notes go ahead. Nothing is cut or skipped; with your own TensorX key you have a queue of your own anyway.
- **The command palette opens faster with many vaults** (#248): it reads a vault's notes only once you type a name (or when a favourite note lives there). A deleted vault's favourites no longer count towards the limit of 200, and the Appearance settings show a colour scheme you picked in the palette.
- **The properties box reads YAML more carefully** (#255). A list it can't read reliably (a broken quote, brackets inside brackets, an empty item) now shows as text instead of being split wrongly; `'it''s'` reads as "it's", and a comma at the end of a list is fine, as YAML allows.
- **Help that says what the commands do** (#264). `help`, every command's help, the tool descriptions and the web console's help now match what the server does. Every option a command takes is listed, each limit is taken from the setting that enforces it, and nothing is promised that isn't there: graph and calendar hide the archive too, `rg --files` lists text files as well as notes, pdfimages states its real time limits, and the console names calendar's write verbs among what it refuses. Agents find features they missed before and no longer plan around behaviour that isn't there.
- **Hardening from the release's review** (#268). A dozen small edges are smoothed. A message given with a write loses invisible characters and runs of spaces, so `history` shows it as written. Checking a TensorX key is limited to a few a minute per person ("Too many keys checked; try again in a minute."). The receipt of a deleted account names TensorX for anyone who had a key of their own, whether or not the server still offers it. Duplicating a note with very long property lines no longer stalls the browser. Hiding the discreet vaults in another tab also closes an open palette, and Recent drops what it no longer shows. `graph --tag` takes as many tags as `/api/graph` does, at most 50.
- **The server has a memory ceiling** (#265). `compose.yaml` limits the server's container to 4 GB by default (`KUMBU_MEM_LIMIT`, e.g. `8g`): past it the kernel ends the server instead of the host running out, and with a restart policy Docker starts it again. Raise it for many users, large vaults or arctic-l.
- **Your own TensorX key has a settings page of its own, External** (#275). It sat under Settings, Vaults, where it was hard to find; now Settings, External holds it as **Embeddings**, and the entry shows only where the server offers keys of one's own. The hint in the Search by meaning dialog points there too.
- **The graph from a note's menus, and a second tap to open** (#276). "Open graph…" is in a note's ⋯, its context menu and its menu in the tree: it shows the column where there is room, else the dialog. In the dialog a second tap on the selected note opens it, beside the one open where the split view fits. On a phone, Read and Write in the top bar are icons, so the note's title keeps its room.
- **Take back in under its note** (#281). When you leave notes out of a publication, each one's **Take back in** now sits under its line, so a list of several stays even instead of the button jumping about with the length of the path.
- **Your memory on claude.ai from the first answer on** (#286). With several connectors on, claude.ai loads Kumbu²'s tools, and its instructions with them, only when it needs them, so a chat that starts with a greeting may not read your memory first. The Welcome note "Connect your AI" and the README now give the one line for claude.ai's preferences that makes it: "At the start of every chat, read my Kumbu² skill project-memory and follow it." The same line helps any AI that doesn't read your memory by itself, such as Grok (#287).

### Fixed

- **Agents see when a calendar entry ends.** The `sh` tool's description, which every agent reads when it connects, now names `until` (an entry over days, or a time with an end), `task` and `upcoming`, and `calendar set --until` to give an entry its end; before, only `help calendar` told them. Start a new agent session after the upgrade to pick it up.
- **Heading links written as Obsidian writes them find their section** (#247). `[[Note#C notes x]]` for `## C# notes | x`, or `[[Roadmap#The roadmap]]` for `## The **road**map`, now leads to the right section in `cat` and its embeds, as in the web app; an exact heading still wins.
- **A tab no longer misses that a discreet vault was hidden again** (#250). When a reveal ended at the very moment the tab's live connection opened, it could lose the "hidden" message; the connection now closes cleanly before it goes.
- **A start-up skill someone else wrote stays an ordinary skill after you stop sharing the vault** (#250). Before, a skill a former member wrote in it counted as yours again and steered your agent at the start of every session.
- **Recent changes keeps what you typed in its filter** (#256). Right after opening the page, the filter could be emptied when the discreet vaults' names arrived, and every change showed again; it now clears only when those vaults are hidden.
- **A skills vault of any name** (#264). `write` and `edit` recognise a skill's text file by the vault marked as your skills vault, not by the name "Skills": in a skills vault with another name, a script in a skill can now be written. A vault that is merely called Skills keeps files like any other. The files API, WebDAV, sync, skill updates, an agent's upload and publishing decide the same way.
- **`links` on an empty folder** (#264). On a vault or folder that holds no notes, only images or nothing at all, `links` answers that no links are broken, instead of "No such file or directory".
- **The Welcome note points to the right place for discreet vaults** (#267): Settings → Security → **Discreet vaults**, where 0.6.0's settings window keeps them. The system skill for agents' uploads and the security documentation now say that any file goes up to the server's bound, not only images and PDFs.
- **More hardening before the release** (#271). Upload links stay with their vault and say less. Published copies follow notes that change while they are made. A move into a skill's folder counts as the mover's write. Discreet vaults keep their favourites, and the console clears a line naming a vault that was just hidden. An owner's own embedding key rests while their account is deactivated. Every account gets a fair share of image and PDF rendering, and a slow drawing is stopped at its time limit. Large lines of links, headings and templates are read quickly. A renamed vault's graph takes less memory, and the memory figure counts it.
- **Closing a window after its vault went** (#272). When you delete a vault in Settings, or leave one, while one of its notes is open behind the window, ✕ now takes you to Your vaults, with a line saying why, instead of back to a note that is gone.
- **Leaving a shared vault from "Shared with you…"** (#277). Leaving through the vault menu's **Shared with you…** panel now takes you to Your vaults, as leaving from the tree does; before, the page stayed on the note you could no longer reach, saying "There is no such note".

## 0.5.0 (2026-11-15)

The calendar, flags and Recent changes make Kumbu² a personal command centre: what's on, what matters and what just changed, and all of it is still just your notes.

### New

- **A calendar made of your notes.** Give a note a day, a time or a week in its front matter (`when`, `until`, `task`, `upcoming`, `tz`), or name it after a day (`2026-11-12.md`) or a week (`2026-W46.md`), and it is in its vault's calendar. The entry stays a note where it lives, so search, links, history, sync, WebDAV and agents work for it as for any other. Week and month views, a small month grid, a tag filter, **Today** and **This week**, and **Add to calendar…** in every note's menu. A to-do is ticked off, reopened, or moved on with **Later**; a board card with a due date is an entry too, its column its status.
- **What's on**: what is overdue, ongoing or coming up across all your vaults, with its count on a badge in the navigation and on the app icon. Times are local: your time zone and your week (workdays, lighter days, days off) are in Settings → Calendar.
- **`sh calendar` for agents:** a vault's week or month, `calendar notifications` for what's on, and `set`, `move`, `close`, `reopen` and `unset` for one note.
- **Flags.** Red, green, blue, purple, yellow, white, done and important, set from a note's menu and shown in its header, in the tree and in Recent changes. A flag is a tag (`flag/red`), so search and agents find it.
- **Recent changes:** every note and attachment across your vaults by its last change, with who changed it and when, filtered by words, vault and flag.
- **The explorer's toolbar:** one row above the folders with **+ New note**, Upload, Calendar, Board, Recent changes, Sort and Find in this vault. Find matches names by every word and by flag; the tree sorts by name or by last change.
- **The open note's own actions:** Rename or move and Delete note in a slim row above the note, in Read and Write mode.
- **Take photo** on phones and tablets, beside Upload here: a whiteboard straight into the vault.
- **Mermaid diagrams,** drawn in notes and in embedded notes, with Show source, and Full size for wide ones. Published pages show the diagram's code.
- **Closer to Obsidian:** links to a single block (`[[Note#^id]]`, and `cat "<path>#^id"` for agents); unlinked mentions below "Linked from" (`backlinks --unlinked`); `aliases` in the front matter, which links resolve by; and `cat` brings the notes a note embeds with `![[Note]]` along, so agents read what people see.
- **A link for your AI** on a published note's reader page: a link that an AI with an HTTP tool can fetch as Markdown, valid for an hour.

### Better

- **Properties at the top.** The properties box folds to "Properties · N" on calendar entries, flagged notes and board cards, whose header already says it in words; **+ Add property** adds one; a block further down that looks like properties offers **Move to properties**.

## 0.4.0 (2026-11-11)

### New

- **WebDAV access.** WebDAV shares under Access → WebDAV: a label, vaults with read, write or maintain, an optional expiry, and a password shown once, with instructions for Dolphin, GNOME Files, Finder, Windows Explorer, rclone, Remotely Save and Nextcloud.
- **Storage quota.** A default limit for every user (`KUMBU_QUOTA_DEFAULT`, unlimited unless set) and a per-user limit in the admin's user list, enforced on every write, whichever way it comes in. Settings show the use, with a notice at 90 %; `df` and `du` in `sh`; the owner can empty a vault's trash.
- **The Access page in three tabs:** keys, apps, WebDAV.
- **Skills.** Instructions in the open Agent Skills format (`SKILL.md` and its files), in a Skills vault of every user and in `_skills/` folders of any vault. An AI finds and reads them through `sh skills`. Skills can be shared behind a link and brought in from marketplaces on GitHub; updates are shown for review, never taken automatically.
- **Ingesting attachments.** A system skill that turns PDFs and images into Markdown notes, their pictures stored beside them and described in words; images come out of PDFs with `pdfimages`.
- **Discreet vaults.** Vaults you mark as discreet don't exist in the web app until a PIN of their own shows them, for a time you choose (5 minutes to "never"). Agents, sync, WebDAV, keys and connections still see them: the PIN hides, it doesn't encrypt. Set up in Settings → Discreet vaults, shown through More vaults…; the Welcome note "Security and privacy" explains it.
- **Closer to Obsidian:** `==highlights==`, `%%comments%%`, maths with KaTeX and footnotes; Copy file path, Copy link and Copy Markdown link in the note's and the tree's menus; a new note takes its name from its first heading.
- **Published notes for AIs:** Copy as Markdown on the reader page, and a hint for agents on how to read a published link.

### Better

- **Search keeps sections whole.** Notes are split along their structure (sections, then paragraphs, lists, tables, code and quotes); a table stays whole or is split between rows with its header in every part; nothing is cut off at the model's limit any more; PDF pages are split by words.
- **A search hit shows the line that matched best,** not the first line of its section.
- **New users start in the vault Welcome,** not in Skills.
- **Hardening from a security review of this release:** tighter limits on what uploads, WebDAV, concurrent writes and very long lines can make the server hold or compute, and a few checks around discreet vaults, app connections, shared skills and published copies.

### Fixed

- **No more requests for a note's old path after a rename**, from the heading or through Rename or move.
- **A note's publication is asked for only when the note is published:** no 404 in the browser's console for every unpublished note.
- **Ticking a task box offline** says at once that the server can't be reached, instead of sending the tick later with an older version.

### Updating

- **Search is rebuilt once.** Every note and PDF is split anew after the update; texts that didn't change keep their vectors, so only what changed is embedded again. Until a vault is done, `semsearch` ranks its notes by words and says how many are pending.
- **New settings, all optional:** `KUMBU_DAV_ENABLED` (default true), `KUMBU_QUOTA_DEFAULT` (default no limit), `KUMBU_SKILLS_MARKETPLACES` (default true), `KUMBU_GITHUB_TOKEN`, and `TZ` for the time `archive` adds to names. See `.env.example` and the README.
