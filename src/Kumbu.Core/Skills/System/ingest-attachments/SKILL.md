# Ingest attachments

1. Find the files: the paths the user gave, a folder, "the new PDFs in /Inbox". Use sh `ls` or `rg --files <folder>` if they were named loosely. Reading is enough to start; writing needs write on the vault the notes go to.
2. Ask once, up front, unless the user said so: for a PDF, a folder of notes (<folder>/<title>/ with an overview note, one note per chapter or topic, the pictures in images/) or one note; recommend by size and structure from `pdf info <pdf>`: one note for a few pages, a folder for a long document. For several files: one note for all, or one each. Where the notes go, if it isn't obvious: beside the source, or a folder the user names.
3. Read the whole source: `pdf info`, then `pdf <pdf> <pages>` page by page, with --images for scans and figures; `img <path>` for an image. Leave nothing out because it seems minor. Tables become Markdown tables, lists stay lists, numbers and units are copied exactly; look at small print in a crop (`pdf --crop`, `img --crop`) before quoting it.
4. Store the pictures. `pdfimages <pdf> <folder>/images/` stores the images the pages paint and lists each with its page and region; small decorations stay out, and --all is not needed. Crop only the regions `pdf info` calls drawing (charts, diagrams, schematics), never its image regions, which the folder form has already stored whole: `pdfimages <pdf> <page> --crop x,y,w,h "<folder>/images/<what it shows>.png"`. `pdf info` lists regions only on pages where figures cover at least 5 %; look at the rendered pages (`pdf <pdf> <pages> --images`) for smaller drawings, and crop those you find, in points from the top left.
5. Write the notes with the write tool: Markdown in the structure of the source, each picture embedded where it stood. Link from the vault's root without the vault's name, spaces as %20: /Work/Pump manual/images/wiring diagram.png is embedded as ![Wiring diagram](/Pump%20manual/images/wiring%20diagram.png). Under each picture, say what it shows in words: the information it carries, a chart's values as a table where they can be read, a diagram's labels. Don't ask about each picture. The first line names the source with a link: Source: [Pump manual.pdf](/Inbox/Pump%20manual.pdf), pages 1–40. Write in the language of the source unless the user asks otherwise; translating loses information.
6. Images as input: the image stays where it is (or moves beside the note with `mv`, if the user wants), is embedded in the note, and what it shows is written out as text or a table. Then ask once, for all of them: "Do you want to add a description or notes of your own?" If the user asks for more (name a plant, look something up), do it with the tools you have, and say what comes from where.
7. Ask once, for all files, what happens to the source: keep it, archive it (`archive <path>`), or delete it (`rm <path>`, in the trash for 30 days). Recommend archive: links follow into the archive, so the Source line keeps working.
8. Report the notes and pictures written, and anything left out and why (an image too large, a page unreadable).

Without write on that vault (the write tool or pdfimages refuses), don't look for another way: give the user the notes' text, and say that the pictures need pdfimages with write access.
